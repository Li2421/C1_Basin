# Ring Exchange：专家—数据闭环审计（v4 采集前）

## 结论

现有 Ring 数据没有发现积分或动作标签错位：对 Base-U、v2、v3、
Base-U+W-v3 全部轨迹，最大
`max |p[t+1] - p[t] - 0.05 u[t]| = 1.87e-9`，没有超出 `2e-5` 的
transition。专家在 episode 成功时立刻截断，不会把成功后的无意义停驻
动作写入数据。

动作幅值为零的比例为 12.5%--16.9%。逐 agent 核验显示这些零动作均发生
在该 agent 已在 `goal_tolerance` 内、等待其他 agent 到达时；没有发现
“尚未到 goal 却停住”的标签。因此它不是 Stage-I 长程全碰撞/超时的主因。

## 发现的 recovery 标签矛盾

旧恢复重查询在已进入圆弧后仍让专家重新选全局最短 CW/CCW 路径。此时
`p × v` 已经给出可观测的切向方向；若重规划反向，几乎相同的物理局部
状态会收到反向转向标签。审计结果如下（只计 `|v_tangent| >= 0.08` 的
agent）：

| 数据 | 切向活跃 agent 标签与专家模式相反 |
|---|---:|
| Base-U | 328 / 667 = 49.2% |
| Base-U v2 | 1506 / 2913 = 51.7% |
| Base-U v3 | 247 / 1123 = 22.0% |
| Base-U+W v3 | 261 / 1149 = 22.7% |

这与“t=0 接近专家、短步合理、长程仍漂向障碍或超时”一致：单步拟合可以
很好，但闭环状态一旦微小偏离就会采到相反的局部环流动作。

## 已实现 v4 改进（不改 MACFlow 架构）

`infer_circulation_hypothesis(p, v)` 仅供**中央专家 recovery re-query**
使用：当至少两个 agent 的物理切向速度绝对值至少 `0.08`，且 75% 以上
同号时，专家延续该 CW 或 CCW。否则（名义、径向、停驻或真正混合状态）
仍搜索两种内部假设并选联合较短实现。

该方向既不存入状态/观察，也不传入 MACFlow；只在 expert metadata 留下
审计字段 `expert_mode_selection`。因此部署策略仍是普通联合
`p(u1,u2,u3,u4 | x)`。

补测：20 个训练 split 状态、交替 CW/CCW 的 81 个满足切向一致条件的
recovery 查询，方向矛盾为 `0 / 81`；Ring 单元测试 `5 passed`。这允许
重新采集训练/开发用 v4 nominal + uniform-recovery 数据。冻结 test 不应用
于恢复采集，也不应在本修复后被重新打开。
