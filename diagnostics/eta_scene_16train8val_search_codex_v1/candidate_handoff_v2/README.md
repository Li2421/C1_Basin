**当前只做分析。本目录不是启动任务的授权，不运行仿真或训练。** 用户将另行让另一位 agent 执行。原目录的 `pipeline.py` 是未完成、已禁用的工作草稿，不是可交付运行器；接手者应按本清单在自己的隔离目录实现与检查。

机器可读清单：`CANDIDATES.json`。每个候选包含物理参数、固定条件、取样约定、独立种子、证据等级、预期需求、失败风险、历史复用入口。补充证据：`EVIDENCE.json`。硬性规则：`STANDARDS.json`。已有锚点与推导详见上一层 `ANALYSIS_ONLY.md`。

## 二、新增方向的依据与失败预期

**F5是最值得优先加入的新增方向。** 旧开放六机r=0.14，在25候选中，sE01（0.972294029,0.942381500,1.406193720）成功率75.00%；sE29（0.338088384,0.553555453,1.204681221）为44.44%；V障碍偏好的sE22（0.551197078,−0.203000475,1.418944003）仅2.78%。V障碍反过来用sE01也比自己的sE22低31.25个百分点。这支持不同需求，但属于旧样本内描述，且还缺24个候选，不能当作完整49候选确认。

F5的r=0.14须先复用原12状态×3控制器×25候选共900格；补到原12状态全49候选最多只缺864格，真正缺失量由官方预检决定。若先仅分析8个发现状态，只构造相应状态的缺失请求，不能为凑完整表顺便跑未需要的状态。

**F6用于找“有一部分η能及时到达，另一部分不能”的过渡区。** 旧方形八机r=0.15、因子2.5，最好75%，共有10个候选在最优5个百分点以内；因子3.0时最好100%，有30个候选在最优5个百分点以内。后者几乎抹平选择需求，因此只考察较窄的过渡区。保持相同起终点分布，仅预先改变时限；不从运行到一半的轨迹人为提前结算。某个候选成功率100%本身不是淘汰理由，关键是是否存在跨场景通用的近最优η。

**F7测试同一交汇处不同方向的通行空间。** 四台机器人仍竞争同一个中心，两个方向受较窄通道约束，另两个方向较宽。它可能改变横向残差与目标加力的折中，但目前只有机制依据；若曲线与等宽十字基本重合，停止扩展这一方向。

**F8测试接触发生的时序。** 九台机器人分三组，起点半径为R−δ、R、R+δ，目标仍为相同圈上的对径点，全部穿过同一个中心。这样改变接触的同时性，不靠平铺独立案例充数。偏移过大会让所有η都成功，这是无信息结果，应停止扩展，而非当作“优化了场景”。

原四方向的互补性已有旧证据：四锚点的完整49候选样本内全局缺口22.92个百分点，对半计分描述为22.69个百分点。它们是事后选出的旧锚点，不是新48配置的实测结论。

## 三、接手执行时不能丢的要求

2. **构造与入口。** 八机保留 `swap8_si_user_fix_20261023` 及载荷 `swap8_single_integrator_user_fix_20261023`、scene_revision、user_scene_revision、moving_policy、geometry_sha256、walls等。圆形按原flow入口和原请求逐字段构造，不迁移成xsc的0.5感知安全层。若复用窄通道/拥挤随机，也保留其原flow格式。新物理参数、实际墙体或代码有变化就登记新的身份，不能冒用旧UID；新墙体必须同时作用于物理步进、控制器墙代价和安全约束。
3. **旧请求重建核对。** 按此前要求，4个文献场景各至少2条已有main_CASES请求，对穿与瓶颈各至少1条，规范化JSON和rollout UID逐字节一致。此步骤只重建请求，不需要重复仿真。保留版本、修正记录与构造代码sha256。
4. **物理与能力门。** 五层证据分别报告：几何有效、单机器人有路、联合可解、控制器成功、死锁解决。后两种未证明的性质不能用前面的性质代替。每个候选3个固定快控制器都要通过能力门：规定的4状态，每个机器人单独运行，种子0与1，每控制器≥95%。不通过就标控制器不适用；不换控制器、不缩机器人、不改半径/容差/动力学来补救同一个候选。无效状态不得默默重抽，除非事先写定的取样算法本来就包含相应拒绝规则并记录拒绝。
5. **统一候选和计分。** η用原ACTIONS精确float64的完整49项，3个控制器为centralized_sampling0、gradient_mpc0、DM0，正式多机器人种子0；场景、状态、控制器分别等权。unknown计失败并附成功上界，不重跑unknown；timeout不能当deadlock。有限菜单结论不能扩展成连续η空间中不存在通用解。
6. **执行加速。** 遵守 `/home/zhihan/research/Basin_C1/docs/exact_engineering_acceleration_20261026.md`。只能用通过逐位认证的工程补丁，不少跑候选、控制器或缩短任务来冒充加速。全认证包括≥3000随机键及实际键链、≥10000投影矩阵数组检查、≥1000分层存档重放、新场景类型的原/改对照。完整既有证书及原/改模块hash都一致时才可走≥200缩减认证。本目录225条只是中断前的部分重放，不是完整证书；没有hash与覆盖证明不能直接套用缩减条件。坏补丁关闭并记录，使用原代码继续，不让加速工作阻断主线。

## 四、节省计算的次序

**阶段0：零rollout排除与复用。** 先核对原始证据和候选身份，低成本检查所有几何设计。r≥0.25的小方箱、已有能力门失败的中心堵路障碍、近乎全失败的极短时限不列入本候选库。未完成配方、构造检查或加速认证时不能发正式作业。

**阶段1：代表配置。** 优先F1–F5，每方向先2个指定训练代表配置，共10个；F6–F8共6个代表仅在现有候选不足时启用。每个代表仍然8个发现状态×3控制器×全部49候选=1176格；不能只跑预期赢家。代表编号在JSON的sentinels中固定。 10个是本优先级的上限，不是最低运行量；先按可复用证据、预期差异增益与实测成本排序，若较少代表已支持4个可扩展方向，尚未启动的代表可保持未运行。先做能力门，再跑发现标签；计时直接使用这些有用的任务，不另造一轮不入库试跑。

**阶段2：补足有价值的训练方向。** 只扩展有能力、有成功窗口、且对现有响应曲线增加差异的方向，补其另外2个训练配置。若只有小样本结论不确定，标为不确定，不声称统计否定；在保守成本排序下继续其他更有依据的方向。最多扩展6个方向的另外2个配置。优先级1总共5个方向只是启动顺序，不是保证它们都通过。

**选择依据：** 看完整49曲线、交叉使用损失、近最优候选集合及对当前全局缺口的增益。赢家名称变化不充分；样本内最高率不同也不充分。如果一个η在所有候选上都近最优，就没有要找的需求差异。小样本全失败、近乎所有η都成功、或复现另一方向曲线的候选优先不扩展；保留全部失败和未扩展记录。

**阶段3：冻结最终16+8。** 从训练发现证据中选4个方向，分别取该方向已规定的4训练与2预留验证配置。训练侧发现缺口以≥15个百分点作为优先选集目标，给独立确认的10个百分点要求留余量；这不是替代正式判定的新阈值。在读验证多机器人标签前冻结全部物理定义、选择规则、种子、16+8清单和统计代码。验证的几何与单机器人能力门可预先检查，但不能用验证多机器人成功率选场景。

**阶段4：独立确认。** 选中24场景各16个新的物理状态×3控制器×49候选。训练侧也用未参与选集的新状态确认。原r=0.14已有0–11状态，故不能直接把8–23叫做未见确认集；所有确认状态使用独立种子与物理哈希，逐一排除发现集、旧已标注状态和训练/验证交叉重复。计分仍采用200次同配对随机对半选择/计分，并计算5000次固定场景状态bootstrap与场景→状态bootstrap。

**正式通过条件不降低：** 训练组和验证组分别相对自己组内选择的最优全局49候选，缺口点估计≥10个百分点且固定场景状态bootstrap95%下界>0。另核对至少一对场景的双向交叉损失都≥10个百分点。按控制器分开附报，不能把均值差异宣称为每个控制器都成立。所有判断读未四舍五入值。

确认失败照实报告这一固定集，不在读完验证标签后换到通过。若以后开始新一轮设计，失败批次保留，原确认集转为开发证据，并换全新的确认状态/配置；它不是本计划的自动补救循环。
