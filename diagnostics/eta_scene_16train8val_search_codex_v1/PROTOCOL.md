# 16 个训练场景与 8 个验证场景：独立搜索

用户授权：2026-10-26，寻找训练集 16、验证集 8 个场景，使两组内部均满足“全局 η 明显不够”；与其他 agent 隔离，使用后续精确加速补丁。仅搜索场景及验证证据，不训练 critic 或生成器。

1. 执行沿用已完成的 critic_pool_supplement_v1：单积分器、分布式安全层、接触门控、3 个快控制器、精确 49 候选、种子 0。能力门用单机器人、状态 0–3、种子 0/1、每个控制器成功率 >=95%。不改成功判据、求解器或时间截断。
2. 两组分开判定：200 次同状态随机对半，一半选择各自 η 或组内全局 η，另一半计分；场景、状态、控制器等权。缺口 >=0.10，且固定场景重抽状态的 5000 次 bootstrap 95% 下界 >0。另报场景→状态区间及更有利于全局的全状态最佳固定候选。
3. 验证侧先复用已正式确认的 8 场景及其 16 个检查状态；这不是全新、未接触验证集。训练候选不得复用这些物理场景定义或状态；需要相同机制的其他参数配置。探索选择会记录，筛选使用的状态不用于新增场景的最终确认。
4. 历史证据优先。已完成训练池 36 场景、验证 8 场景的标签、配置、模型和报告只读；当前任务不需要旧 checkpoint 推理，因目标是标签曲线异质性。缺失证据是训练侧足够多的稳定、互补场景。历史不全 49 的状态不得填零。
5. 新场景候选为静态障碍径向交换、十字通道、开放交换、方形随机。只改声明的几何/任务参数；不通过能力门或几何有效性不得收录。筛选 0–3，最终确认 8–23。场景选择在读取 8–23 的标签前冻结；若确认失败，保留失败并明确另起设计迭代。
6. 精确工程加速按 docs/exact_engineering_acceleration_20261026.md：四项独立开关、>=3000 随机键、实际整链、>=10000 投影矩阵核对、>=1000 分层存档重放、新配置原/改逐位对比。失败补丁禁用并继续。所有源文件只改本目录；官方共享库不改。
7. 所有实际新 rollout（包括筛选）必须先官方登记和 preflight，只执行 genuinely_missing；worker 写官方 journal，一个 merger 合库。认证重放只用于认证，不重复入库。保留所有轨迹、数值失败计 unknown，timeout 不写为 deadlock。
8. 用户总 CPU 限额 18；本任务最多 8 个单核 worker 加协调者，并根据同用户其他计算作业减少并行；其他 agent 的目录、作业和数据库已存在行均不改。输出、状态、失败、哈希都写本目录。初始探索最多 30000 正式 rollout，最终确认最多 40000（能力门与认证另列）；不足时记录证据缺口，不声称成功。
