# 真实安全域与机制解释边界

本轮使用的联合速度可行域是逐机器人原投影集合的笛卡尔积，而不是单个耦合相对速度 CBF QP。依据是私有副本 `generated/backend/swap_safety.py::local_problem` 的原生产实现：对机器人对，记 d=p_i−p_j、h=||d||²−d_safe²，分别要求

```
2 d·u_i >= -0.5 gamma h
-2 d·u_j >= -0.5 gamma h
```

相加得到相对速度约束 `2 d·(u_i-u_j) >= -gamma h`，但反向蕴含不成立。例如 h=0 时，两机器人取同一平移速度 v，耦合相对速度约束允许该动作；若 d·v≠0，上述两个独立约束至少一个不满足。因而不能把论文中对另一可行域证明的协调旋转/平移能力直接搬到本系统。

这也给出三项需要用轨迹核验的解释，而非预设结论：

- 群中心刚性旋转在耦合相对速度约束下可能保持各距离，但逐机器人责任分摊后，其分量未必都被允许。新增列有线性独立性，不意味着原安全投影会保留它。
- 活跃约束切向投影只保留活跃行的零空间。单机二维行矩阵秩为2时该列为零；单侧不等式可行域仍可能允许向外运动，不能把零空间为零称为局部无路。
- 原字典角色对只在 `role.pair is None` 时选择。失活后不会自动改选下一对；冲突对旋转、让行、速度错峰可能只服务第一对冲突。不能把一个固定角色策略的失败推广成所有角色协调机制的失败。

目标侧转从起步即可非零，群中心旋转需要接触冲突图连通，因此两者的整局差异还可能含激活时机差异。从初始状态成功不等于从同一个真实死锁态恢复。此轮 Oracle 是固定系数、状态依赖列的有限搜索；没有阶段切换消融，不能据此排除时序方案。

原字典的活跃约束切向投影默认种子就是目标侧转。没有近活跃行且安全速度球不近活跃时，两列相同；有近活跃行时才通过零空间投影产生差异。因此这两列的组合可能体现“随约束状态改变侧转增益／分布”，而不一定是每个状态都有两条新的独立运动轴。近活跃阈值是归一化速度slack≤0.025m/s，速度球在安全输入模长≥0.475m/s时加一行法向；SVD绝对阈值1e-12、相对阈值1e-10。它们保持原字典定义。

局部净空列是原局部约束邻域中距离softmin总和的梯度，机器人对贡献两端，墙使用最近墙段距离；平滑尺度为0.25倍机器人安全间距。局部邻域在0.5m处截断，最近特征切换和邻域切换处不应声称全局光滑。原地等待列只软抵消该让行者的安全参考动作，仍可能被其他修正和最终投影改变，不等于硬HOLD或BLEND。

`STATIC_MECHANISMS.json` 使用保存的真实失败三列轨迹做秩、角度、逐列投影保留率及32顶点数值检查。不新跑物理环境，不把浮点残差估计、有限顶点结果或未找到成功解释为数学不可能性证书。

论文完整机制端口保留各自 controller/safety，因此其成功轨迹不是“原 C1 逐机器人安全域允许整条脱困轨迹”的证据。只有经原 C1 安全层执行并完成的 rollout，才是该层下本任务的构造性成功见证。

新增的 `ROUTE_UNKNOWN_DIAGNOSTICS.json` 对路线异常的最终保存状态逐台复查原 `valid_points` 和 `path`，并记录原路线图可见节点数。若当前位置几何有效、却无法连接原路线图，而一个仅用于诊断的短可见连接段接回原路线图后确有路径，则这是路线图覆盖缺口的构造性证据。诊断连接段从未输入控制器，不用于重跑、修复或改变任何候选的结局；原 unknown 标签保留。该几何证据也不是多机器人联合可解见证。

32 顶点表额外保存以原约束近活跃行构成的法锥非负最小二乘残差，近活跃阈值绝对值为 1e-7；速度球在零速度处不活跃。近活跃集合和浮点残差不是精确法锥成员证书，零速度原线性不可行时也不应用此残差声称零投影。全局秩与未到达机器人子矩阵的秩分别报告，避免已到达或无关机器人贡献的方向掩盖局部阻塞。
