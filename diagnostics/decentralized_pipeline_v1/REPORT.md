### 新管线失败构成

- F10：D-shared / 集中式 TT 的 timeout 为 872 / 783，unknown 为 0 / 2，停滞 episode 比例为 87.28% / 40.62%。
- F13：D-shared / 集中式 TT 的 timeout 为 616 / 529，unknown 为 0 / 4，停滞 episode 比例为 19.42% / 0.00%。
- S300：D-shared / 集中式 TT 的 timeout 为 282 / 123，unknown 为 0 / 4，停滞 episode 比例为 24.44% / 2.90%。
- S500：D-shared / 集中式 TT 的 timeout 为 219 / 58，unknown 为 0 / 4，停滞 episode 比例为 20.65% / 1.23%。

局部约束要求每个机器人独自承担半份 pair 下界；集中式约束只限制两者贡献之和，允许在机器人间重新分配避碰责任。因此局部可行域增加了个体责任限制；它是本轮结构差异。停滞和终止构成提供失败模式诊断，不足以证明经典力平衡死锁。

停滞：执行速度 <.01m/s、未到达目标且连续至少 40 步；累计时长包括该合格低速段的全部步。数值失败前的诊断段保留，受未知后续截尾影响。人数为每条 episode 至少一次合格低速段的不同机器人数。

## 7. 解释边界与交付

D-shared 和 D-local 的安全优化、修正与切换均由机器人本地计算，但策略仍需要共享全队观测和公共 RNG/时钟；不能声称完全独立观测部署。D-local 只限制安全约束和 B_rel 的 1.5m 邻居，不改变策略观测。每对约束各承担一半、假设邻居零速度；本轮未交换投影动作。物理、成功、碰撞与事件语义均未改动。controller payload 中遗留的 chain=FF 是复制原 Flow profile 的描述字段；本轮实际执行以 conditioning/execution_semantics、冻结 runner/pipeline 哈希及 TT 一致性门为准，未将该字段用于缓存复用。见 METADATA_AUDIT.json。

数据链路：main_PLANNED_ROLLOUTS.json → main_CACHE_PREFLIGHT.json → main/raw + main/traces → journals → 单进程官方 merger → main_CACHE_POSTFLIGHT.json。专家独立执行身份走同样流程。MERGE_RECEIPT.json 核验 DB、原始记录和 unknown 一致，unknown 不触发补跑。results.json、rollout_metrics.csv、analysis_arrays.npz、figures/ 为分析产物；所有历史源文件保持原样。
