# 用户要求的事后修订执行增补

本增补由用户在审阅原预注册结果后明确要求，属于事后修订与开发证据，不能冒充预注册验证。原PREREGISTRATION、源码、菜单、COMPLETED_*、raw、trace与收据不改。修正指令已完整阅读，新增prompt只在完整性审计中记录os.stat。

实例归类以INSTANCE_CLASSES_REVISED为准：基线成功上界≤5%的合格实例，用失败局中未到达机器人·局的5秒/.05主分类多数，区分安全层全局失败、墙前陷阱、controller级失败。只从去除分析中排除最后一类；九格敏感性逐个列出，集中/分布式互为旁证。原封存口径保留并明确区别。

修正语义与固定Rc数值在CORRECTION_REVISION.md和CORRECTION_REVISION.receipt.json封存。只有Brel按接触冲突开关归零，三个分量原公式、η值、两次投影、责任系数、速度/加速度与物理、到达停止、进度切换及6/7时限回退全部不变。新的非零语义使用新controller身份；状态/物理身份和随机数配对继续沿用对应原状态。η0经32条完整名义控制器+物理轨迹逐位回放验证，保持原执行身份直接复用，已有unknown不重试。

新菜单15动作，前12个逐项保持原菜单，末3个为全程η10、全程η13、人定η13→η10/.968。η逐位取FIXED_ETA，encode沿用原19维，模型结构、36组来源拟合、17/23/41三个初始化、2000训练步、嵌套留一类型、checkpoint选择不变。训练每类前2实例、原32训练state；48实例评估，原评估state，两个seed配对。集中式不重新学习。冻结模型与逐state选择在首个新评估请求前封存。

执行身份以安全层、原物理/名义控制器/数值实现和完整η切换日程为准，不把纯报告方法名当成新执行。固定修正与菜单12/13/14规范为同一执行日程；菜单0规范为原safety。和原learning_design.make_case相同，可在顶层case.method标明learning_action/learned_scene，controller_payload.method仍是规范执行日程。相同日程、同状态/种子/执行层且全部指纹匹配时直接走官方精确复用，不重复rollout。随机两η动作各保留原动作日程身份。

顺序严格为：单元/静态门与实例归类 → 分布式修订固定四场景 → 分布式修订学习窄通道/拥挤随机/门口 → 集中式修订固定四场景 → 圆形修订学习 → 非主线第二阶段/变体 → 图、最终报告、结束审计。只加安全投影与原语义已完成结果复用；原语义圆形旧标签只保留落盘数据，标用户决定停止：修正语义修订，不做旧评估、不恢复其旧队列。运行中旧局完成后自然退出，不硬取消。
