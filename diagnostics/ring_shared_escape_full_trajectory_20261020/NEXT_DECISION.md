# Minimum next validation for an RSS mechanism claim

The old Ring domain is excluded from all saved episodes by fixed-goal geometry. The new broad circulation reference is safe but its simultaneous four-agent action cone is rare in successful TT episodes, including whole-type critic holdouts. More trajectory counting on the same cone will not bridge the theory-to-method gap. The next step should target **staggered or asymmetric coordination** while retaining a controller-independent state/action definition.

First, perform a read-only discovery analysis on round27's 32 states and saved TT trajectories, blind to episode outcomes while defining features: agent angular order around the obstacle, per-agent signed angular progress, radial detours, pairwise clearance, and which agents temporarily wait or move opposite to the eventual common direction. Use actual 48+48 polygon CBF rows, six pair rows and speed balls to define a *finite union* of safe stage action sets with explicit stage guard and exit. A priority/order hypothesis can be tested, but a label such as “successful controller action” must never enter the definition. Freeze the geometry and thresholds before inspecting any new held-out action records. Existing 1c/3c results in this audit are already exposed, so their reuse would be retrospective external application, not a fresh prospective confirmation.

Then run a bounded **action-only** compatibility audit at saved state/key/controller tuples: at most eight TT types × two base instances × two initial states × three predeclared physical steps = **96 state-controller-step tuples**. Prefer one additional whole-type holdout if its source checkpoint and key are archived. First compare reconstructed original nominal and final TT actions with stored actions on the *same* tuple; reject incompatible checkpoints, frame transforms, RNG or Safety QP. Only after this gate passes, reconstruct `a_safe`, all three B columns, original selected η and each frozen menu η at those same states. A menu of at most 15 arms would require at most **1,440 candidate projection calls**, plus ≤96 anchor projections and no physical integration. The archive's exact η/state/controller/seed identities and `shared_rollout_db/README.md` should be checked before any probe; the rollout DB preflight is mandatory only if an actual episode rollout is later proposed. Estimated compute is order **minutes of CPU** for projections once runtimes load, but checkpoint loading and native nominal inference may dominate; record measured solver/network calls and elapsed time in the next manifest. Do not substitute generated noise keys or run env.step.

At each compatible tuple, report stage membership, whether `E_m(x)` is nonempty, selected TT membership, raw correction and anchor effects, exact frozen menu coverage, `r_m`, `d_c` and the strict sufficient certificate when its assumptions match. A menu miss remains inconclusive about the continuous parameter box; proving box infeasibility needs a separate global certificate. Link each tuple back to its saved stage continuation and outcome without treating timepoints as independent episodes. Summarize by base Controller instance and type; any uncertainty interval should resample Controller, state and episode clusters.

Only a predeclared stage with nontrivial coverage on independent Controllers, measured TT entry into its safe action set, and sustained exit on matched trajectories would support “shared escape structure explains cross-Controller correction success.” If the staggered candidate again has no coverage or no TT realization, the RSS claim should remain the conditional existence/exploitability theorem plus a documented negative mechanism audit. **No new episode rollout, training, or method change is authorized or needed for this next read-only/action-only step.** If episode rollout later becomes necessary, provide the exact planned-request manifest, cache preflight, missing-count budget and expected information gain for approval before running it.
