## 共同执行器的身份与随机流

- 基准甲旧 `make_new` 的随机流默认来自旧 `state_uid`，不能换成基准乙采用的 `rng_physical` 哈希。即使位置、种子相同，重命名共同环境 scenario 也会改变旧 state UID。新请求需要另存并沿用按旧 scenario payload 重建的 `rng_state_uid`，并用强制复演核验，不能仅凭种子编号相同声称 matched random seeds。
- 基准甲原执行循环给名义控制器真实目标，不含基准乙的路线目标钩子。环境适配不能擅自引入新的路线引导来改变我们方法的旧执行语义；论文方法的地图/路线输入按共同信息约束逐项登记，Chen 保留原规划器。
- 补充源码核验：学习侧 `learned_obs.py` 已包含地图导航场 `Field`（分辨率0.025 m、特征WAY=0.5 m），不是没有路径信息。保持学习侧真实目标与该观察不变；按协议给基准甲无自有规划器的论文方法启用现成v3路线引导，Chen仍用自有规划器。两种路线表示的具体构造应在信息表写清，不能声称它们每一步的路线向量逐位相同，也不能把无路线的直奔目标端口当作信息对等的论文主对照。
- `core.py` 仍由交付标记阻止数值导入。它先固定官方数据库，再预载复制的研究包到规范命名空间，以防旧模块插入源码路径后意外解析到其他 diagnostics 或 PoC 影子数据库。
- `prepare_execution.py` 的206项副本记录在 `EXECUTION_COPY.json`；MACFlow工具通过保留兄弟目录结构实现原文件逐字节复制。ports中两项仅替换历史绝对输入根路径。尚未完成的环境和前缀核验不得写为通过。
- 历史学习侧标签无完成时间、轨迹。仅复演后得到的新时间不能冒充旧文件中已经保存的时间。环境检查必须分列结局对旧标签的核对、复制原实现与共同环境的动作/轨迹核对，以及旧时间本身不可直接核对的限制。

## 继承的墙体碰撞定义差异

源码与全部状态配置核验见STATIC_WALL_MARGIN_AUDIT.json。异质场景60张中32张的外层配置与几何配置不同，其中18张方形场景的机器人半径在外层为0.12、0.13、0.14、0.15、0.16 m、几何配置为0.05 m；冻结step对机器人之间使用外层半径，对墙体使用geometry.margin。这18张分布在训练10张、验证2张、测试6张（以JSON逐项计数为准）。另14张十字路口主要是墙半径字段不同。17类的49张地图未发现该配置差异。
