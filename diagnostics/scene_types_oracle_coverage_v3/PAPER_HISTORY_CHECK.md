# 追加论文对照的历史证据与必要性

用户最新要求四列族完成784案例后先跑之前指定的五篇论文六版本，观察场景是否偏易；这覆盖v3文档原先不跑论文的范围限制，其他保护和90k总新rollout上限保持。

已检查 scene_types_basis_dimension_v1 的论文参数冻结、原始结果、端口与占据栅格修订；scene_types_basis_dimension_v2 的作者版本锁定、来源复查、单元检查、局部根因与异常处理适配。v2未运行任何实际论文controller；不能声称其实现已经真实验证。旧v1论文标签存在4倍时限、路线信息不等和大量异常；本次使用根因修正、共享路线信息和逐机器人停一步恢复，故旧结局不作为新端口的精确缓存，仅复用源码、来源、参数及诊断证据。

冻结参考默认与v1开发选中参数；完全相同的配置合并，另保留v1已有Chen物理长度映射选项作为独立固定profile。所有profile在本轮论文结果之前登记，无新参数搜索。Wang与风险方法的参考默认值没有完整作者公开数值默认保证，明确标为公式端口参照，不称作者默认。

先在每个类型基准档状态0做真实联合pilot（是后续全队列的精确子集），再做每档状态0所有机器人逐台单机诊断，最后全部49档×状态0–7的联合比较。单机诊断只有一个初态，不冒称v2完整四初态适用性认证；未通过的场景仍在总表，单独标记，不能把它的失败当作死锁或场景本身难的证明。

作者代码和依赖只读，不训练任何模型，不启用GPU。运行时版本按profile固定到本轮不可变副本；单个方法修正只改变其本地适配版本，不覆盖旧结果。每个案例单独解释器，控制作者全局模块、缓存和规划随机种子；所有输出、绘图缓存与工作目录重定向本轮路径。原C1 nominal、basis、生产安全层、动力学和成功判据不变。
