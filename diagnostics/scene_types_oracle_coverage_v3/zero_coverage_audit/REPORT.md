# 零覆盖场景：联合可通行性与当前名义控制器审计

2026-10-28。审计启动时四列族在 7 个梯子场景覆盖为零，其中只有“窄门·两组对向互换”整类三档均为零。搜索仍在进行；零覆盖不是联合不可解证据。本补充诊断不改场景、控制器、修正列、安全层、时限或任何 Oracle 标签。

**已找到原时限内的联合可行数值见证。** 窄门每侧3台、共6台的状态3（`xsc_stb_t08_l0_w000`），构造轨迹在 **39.30秒** 首次满足原成功判据，原时限为 **42.65秒**。逐步调用实际生产 `RN.SwapSafety` 构造约束行，全部通过；最大速度0.4995m/s，原上限0.5m/s；按原连续扫掠公式计算，机器人间最小净距0.023615m，墙体最小净距0.020189m，最小CBF残差为正的5.0721e-6，动力学残差1.102e-16。

这是一条**显式专家轨迹的数值可行见证**，没有运行名义控制器、没有调用投影求解器、没有调用 `env.step`，不计入论文方法或 correction 成功率。它证明的范围是这个具体初态的原几何、动力学、速度、CBF行与时限可共同满足；不证明其余初态均可解，也不证明当前四列的连续系数空间无法解决该初态。

复核文件：[ORIGINAL_ROW_VERIFICATION.json](ORIGINAL_ROW_VERIFICATION.json)。轨迹位置、动作及sha256保存在其中指向的NPZ；起点与冻结状态逐位相同。793步检查轨迹在第786步首次满足所有机器人距目标不超过0.08m，完整轨迹到第793步到达精确目标。

## 几何含义与结论边界

窄门实体开口0.30m，机器人半径0.10m；原墙体占据与碰撞余量合计使中心需距墙至少0.111667m，CBF再加0.0001m缓冲。门内中心可用横向宽度约0.07647m，足够单列通过，但不足以让两台在门内并排交换。两侧房间有等待空间，所以应检验的是队列协调与时限，而非仅以门宽断言联合不可解。

当前明确证据：至少一个四列零覆盖初态在原联合速度可行域与时限内可完成。其四列失败仍可能来自有限系数搜索、共享系数/方向表达、固定时序或短预测窗等因素；单凭此见证无法分解这些原因。没有把专家规划器作为新nominal，也没有把专家轨迹反向加入Oracle候选。
