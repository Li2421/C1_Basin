# 最小验证实验：controller × 几何的可辨识性（2026-10-11）

**结论：被检验的说法只得到部分支持，其中关于根因的核心推断被证伪。**

- **成立：** controller 和 η 对 Q 的作用随几何系统性改变。即使在同一个场景里只改一个几何参数，也是如此。
- **成立：** 增加单个几何内的数据不能替代几何多样性。
- **被证伪：** “几何太少导致不可辨识、跨几何外推必然失败”这一判断不成立。
  - 学习器只要能看到几何坐标，并且知道精确的 controller 身份，仅用 3 个几何、甚至单侧外推，就能把大部分结构迁移到没见过的几何上。
- **因此：** 四场景 LOSO 失败不能用“环境数量少”本身来解释。这个根因判断需要修正，见 §4。

## 1. 设计与完整性

- **预注册：** `PREREGISTRATION.md`（sha256 前缀 7a593cea）在任何新 outcome 出现之前冻结。pilot 只按预先写定的信号规则决定宽度网格（`main_grid.json`）。
- **唯一变化的量：** Double-Bottleneck 的 `bottleneck_width`。
  - 以下全部固定：4 个 agent、动力学、horizon、安全投影、FF 积分、OrthoFlow3、评价器、噪声律、物理初态，以及在各宽度间共用的 common random numbers。
  - controller 是 5 个 endpoint-matched goal-reference 算子，代码与四场景研究相同。
  - η 使用 K4 面板。
- **复现门槛：** 在宽度 0.50 下，与存档 raw 记录逐字节一致（6 条 rollout × 2 条执行路径，`reproduction.json`）。
- **Pilot：** 8 个宽度 × 8 个 state × 20 种 (C, η) × 1 个 seed，共 1,280 次 rollout。
- **Main：** 14 个宽度（0.72–1.62）× 16 个新 state（与 pilot 不重叠）× 20 种 (C, η)，共 13,440 次 rollout。
  - 宽度分工：test 为 0.90/1.08/1.26/1.44，FEW 为 0.72/1.20/1.62。
- **数据质量与工作流：**
  - 0 次碰撞。
  - 16 次 numerical_failure，作为 unknown 保留，没有重跑。
  - preflight 与 postflight 中 ambiguous 都为 0。
  - 全部 rollout 已经 journal 并 merge 进 `shared_rollout_db`（pilot 1,280 条，main 13,440 条）。
- **学习器：** 预注册的 MLP（3×128，5 个 seed 集成），输入为 [宽度 w, 初态, C one-hot, η]，只用 Slurm CPU 训练，不调参。

## 3. 探索性分析（未预注册，`exploratory_results.json`）

- **η 排序在同一个几何族内反转：** η10 − η15 在 w = 0.90 时为 −0.36 [−0.39, −0.33]，在 w = 1.26 时为 +0.13 [+0.09, +0.16]，在 w = 1.32 时为 +0.19 [+0.18, +0.20]。四场景研究中 “DB 偏好 η15、Ring 偏好 η10” 的现象，在单一几何参数上也能复现。
- **测试 state 与训练 state 完全不重叠时，结论不变：** MANY 的 B2 为 0.87，FEW 为 0.75，FEW×2 为 0.75，EXTRAP 为 0.63–0.65。
- **这个几何族几乎不依赖 state：** 在有信息的宽度上，state 相关能量只占总方差的 0–6%（0.84 是边缘宽度，例外）。所以这里检验的是 (C, η, 几何) 结构，**没有检验 state 条件化**；难度明显低于四场景。

## 4. 对之前根因判断的修正

**被证实的部分：**
- controller 和 η 的作用是 controller × 几何的性质：只改一个几何参数，算子效应模式就会系统性改变，η 偏好会反转。
- 增加单个几何内的 state 或 seed 无效。

**被证伪的部分：** “几何数量少，因此在原理上不可辨识”。

- 在一个平滑的单参数几何族里，只要几何坐标对学习器可见，3 个几何（其中一个没有信号）或单侧外推，就能迁移大部分结构。

**新的主假设（待直接检验）：** 四场景的失败不在于环境数量少，而在于不存在一个被表示出来、各场景共享的几何/机制坐标。

- 四个场景在拓扑、agent 数、horizon、速度、监测器和基础 Flow 上同时不同。
- critic 通过 entity token 看到几何，held 场景的关系没有一条可以内插或外推的轴。
- 在这里，学习器拿到了显式的宽度坐标，因此“几何数量”不再是瓶颈。这把重点从“数据或环境数量”转向“几何与机制如何表示”。不过这一点目前还是由排除得到的推断，需要直接检验。

**下一个最有判别力的检验（不需要新 rollout）：**
- 把项目实际使用的 entity-encoder critic 用在本实验的 DB 宽度族上，输入从墙体 entity 得到，不给显式 w，与本 MLP 做同样的 MANY/FEW/EXTRAP 对比。
- 如果项目 encoder 在这个“容易的、有坐标的”几何族上也外推失败，说明表示本身就是瓶颈。
- 如果它也成功，问题就更集中在四场景之间缺少共享坐标上。

## 6. 后续检验：项目 entity-encoder critic（预注册见 `PREREGISTRATION_ENTITY.md`，结果见 `entity_results.json`）

本节不新增 rollout，复用 main 阶段的 13,440 个标签。

**设置：**
- 网络：项目 `Critic('state_field_compact')`，即 `rep.Encoder`。
- 几何输入：几何只通过各宽度的墙段 obstacle entity 进入，不提供显式宽度 w。在宽度 0.50 时，这些墙段与项目存档模板逐值一致。
- controller 输入：每个 agent 一个 5 维 one-hot。
- 训练：沿用项目原设置（6000 步），3 个 seed。

**各组 B2（括号内为 B1）：**

| 组 | ENT（只有 entity） | ENT+w | MLP+w（前一实验） |
|---|---|---|---|
| MANY | 0.91（0.69） | 0.91 | 0.88 |
| FEW | 0.75（0.33） | 0.76 | 0.80 |
| FEW_x2 | 0.75 | 0.76 | 0.79 |
| EXTRAP 平均 | **0.63** | 0.58 | **0.63** |

**预注册判定：**
- **R1 成立。** 在有共享几何坐标的几何族中，项目的 entity 表示不是瓶颈：只靠墙体 entity 就能像显式 w 一样外推。
- **R2、R3 不成立。**

**附带观察：** 从宽到窄的外推（EXTRAP_B）在三种学习器上都选错 η（η 选择 0.175，oracle 0.575）。这正好落在 η 偏好随宽度反转的位置，与几何表示方式无关。

**对根因判断的影响：**

| 候选解释 | 结论 |
|---|---|
| 场景数量少 | 已排除 |
| 环境内数据不足 | 已排除 |
| controller 信息不足 | 已排除；本实验中 controller 身份是精确的 |
| 项目 entity 几何表示 | 已排除 |

剩下的主要假设：
- **各场景不在同一个共享的几何/机制坐标上。** 四个场景在拓扑、agent 数、horizon 和基础 Flow 上同时不同。
- **state 条件化本身的难度。** 本几何族不检验这一点。

下一个直接检验：构造“同一机制、不同拓扑”或“同一拓扑、不同 agent 数”的几何族，测试跨族迁移；或者换一个强依赖 state 的几何族，重做本实验。
