# 操作性断点恢复与身份兼容性

为同时保留完整请求和执行“连续30分钟无新结果即撤销重提”，新增操作性断点包装。`runtime_new.py`、登记的场景、物理状态、控制器配置、eta和种子均保持原字节与身份。新文件 `runtime_checkpointed.py` 是静态派生副本；`CHECKPOINT_BUILD.json` 和 `CHECKPOINT_RUNTIME.diff` 记录全部插入，逐字逆变换恢复原入口。数值运算、调用顺序、物理步、事件、成功判据和异常记unknown的逻辑不变，没有给旧模块打补丁。

保存内容为整个环境、完整actor/规划器对象、轨迹与安全证书历史、初始距离、下一步索引和累计活动时间。恢复后使用原状态UID/种子重新生成相同根随机键，继续使用原步索引。完整环境与规划器作为同一对象图序列化，保留内部引用。文件只写本轮 `operational_checkpoints/`；pickle完成并fsync后才原子发布SHA256收据。恢复先核对完整case身份、源码和文件哈希。TERM/USR1在安全步边界保存并退出，未完成请求不产生科学标签；只有完整结果才走官方journal及单进程merger。

保留同一rollout UID的依据是科学执行语义逐位相同，而非将断点当作新控制器。新增操作性实现及验证收据的SHA256另随最终结果的 `operational_resume` 保存，模型冻结与结束核对同时覆盖它们。原始输入源码哈希继续逐项校验，旧元数据行不修改。发生真实数值失败仍按原入口输出unknown且不重跑；撤销或断点不冒充timeout、deadlock或unknown科学结果。

验证包含：PA和CBS各在Gap N=2/4/6上分别以四个独立进程完成连续参考、暂停37步、从37步恢复并暂停83步、从83步恢复至160步；逐项确认恢复起点，除墙钟计时外的完整结果、动作、轨迹、几何与安全证书逐位一致。另有13个新场景×2规划器的初始对象序列化核对，以及真实长单局第1821步断点的只读对象关联和历史长度核对。外推N=10只检查初始定义及尚未运行的actor，没有调用多机器人action或读取评估结果。见 `CHECKPOINT_REPLAY_CHECK.json`、`CHECKPOINT_PLANNER_SCOPE_CHECK.json`、`CHECKPOINT_STRUCTURAL_READBACK.json`。

该包装只用于新场景的PA/CBS，文献场景仍走原入口。原有10局逐位重放证据保留。调度器继续以完整结果而非心跳/断点判断30分钟无进展，并逐次缩短Slurm时限；55分钟前停止领取新组的约束保留。断点不保存原生搜索函数内部的未完成查询，因此单次原生查询本身超过撤销窗口时仍可能无法推进，必须如实报告。初次启用包装前有一次提前撤销旧worker，原因与丢弃的计算开销保留在 `PILOT_CHECKPOINT_UPGRADE.json`，不伪记为完整单局耗时。
