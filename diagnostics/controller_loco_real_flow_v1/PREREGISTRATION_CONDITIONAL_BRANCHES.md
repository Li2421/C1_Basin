# Conditional Stage B/C preregistration

Frozen while Stage A workers were running, before Stage A labels were merged, before fitting or reading Stage A endpoint outcomes, and before any B/C outcome. This does not replace `PREREGISTRATION_STAGE_A.md`.

## Branch decision

Use `GATE_RESULTS.json` and the Stage A simultaneous max-T result. If fewer than two necessary folds, B and C are NOT EXECUTED. If at least two are necessary and no R3/R4_action/R4_openloop/R3+R4_action arm satisfies all four lower-CI requirements, execute B only. If an arm satisfies all four, execute C only. No branch is chosen by Q MSE.

## Stage B: more source Flow controllers

Use the other seven P1-compatible Flow checkpoints outside the [40%,95%] window (their names and exact P1 profiles are the complement of the original seven in `P1_EXECUTION_PROTOCOL.json`). They provide source supervision only, never become held test controllers. Reuse the same 128 S_train states, same balanced per-state eight-η masks, and seeds0–3; 7×128×8×4=28,672 exact requests. Run shared DB preflight before workers; cap new rollouts at30,000, do not rerun cached/unknown. All seven static R3/R4_action/R4_openloop features are computed on S_train and the source P1 validation states with `env.step` forbidden. Their outside-window success rates are kept, not filtered after outcome.

For each original necessary fold, retrain the five Stage A representation arms on its six original source controllers plus all seven additions, using the identical architecture, optimizer, 12,000-step schedule, three fit seeds, balanced controller sampling, source-only normalization and source-only P1 validation NLL checkpoint selection. Evaluate only the already frozen 64 S_test states and seeds4–7; compare Stage B to Stage A, source prior/nearest source/R0 and matched versus mismatch with the same paired unknown and 16-comparison simultaneous max-T procedure. This is a conditional follow-up on an opened endpoint panel and is reported as DEVELOPMENT, not a new independent confirmation. A Stage B success diagnoses possible controller coverage but cannot alone prove it causal or universally sufficient.

## Stage C: independent confirmation if Stage A passes

Freeze Stage A passing arm(s), all fold-specific checkpoints, preprocessing, η-source prior, nearest-controller rule and static query code. Draw wholly new natural Ring development states from seed 2026160000+i, excluding all existing DB content hashes. Because the cap is 10,000 and at least two necessary folds are required for the main gate, allocate exactly 64 **state–controller panels total** across necessary folds, in original controller order as evenly as possible (e.g. 32 each for two folds); all folds use the same new physical state sequence but only their preregistered first `n_k` states receive labels. This is the smallest budget-feasible interpretation of the originally requested 64 new states per necessary controller; per-controller precision is correspondingly lower and must be reported. Each panel uses K16×Q8, gross 8,192. If exact preflight reuse occurs, submit only genuinely missing. Seed0–3 may choose target fixed comparison; seed4–7 are the independent endpoint. No retraining, no representation selection, no checkpoint tuning, no changed threshold. Recompute the four contrasts for each Stage A passing representation, matched versus six source mismatch descriptors, and state-cluster max-T simultaneous 95% intervals, with all necessary folds weighted equally. Confirm only if all original four lower intervals stay positive. Unknown is bounded and paired as in Stage A. Stage C is independent state/seed evidence but has smaller per-fold state count due the hard rollout cap.
