# Native v10 runtime correction before full rollout

The initial static-feature array task for `base_u_v10_local_macflow` failed before writing features because this controller's frozen P1 execution profile has no `adapter_manifest_path`. All 1,536 P1 pilot cases for native v10 were exact cached labels, so the P1 worker never instantiated an adapter for it. The correct historical execution is `diagnostics.controller_q_diversity_v1.runtime.native_runtime('ring_exchange')`, which returns `FourRingRuntime` with the same native v10 checkpoint path and H700. The new Stage A `features.py` and `run.py` were changed to use that native runtime for this one controller while leaving its frozen controller UID and semantic profile untouched. No historical file changed. The partially completed 98-case timing pilot was stopped before the fix; its already written raw/journal remain and the pilot resumes by exact case UID. All other six feature tasks completed without error. This is an implementation compatibility fix, not a change to the preregistered controller set, data, success rule, or hypothesis gate.

Additional static equivalence audit before critic fitting: P1's cached v10 validation R3/R4_action features had been computed through an adapter manifest even though its exact rollout UID denotes native execution. `native_validation_equivalence.py` recomputed both on the same 24 validation states using the exact native runtime, with `env.step` forbidden. The maximum absolute difference was **0.0 for R3 and 0.0 for R4_action**; thus the adapter feature cache was exactly equivalent in these measured coordinates. The new study's validation NPZ now contains the native recomputation. See `NATIVE_VALIDATION_FEATURE_AUDIT.json` and Slurm log `native_feature_audit_19408.log`.
