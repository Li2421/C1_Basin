# 资源调度补充

用户要求所有任务合计实际18 CPU。本轮持续只暂停自己的 r36 进程组，保留仿真现场；其他任务不发信号、不取消。Slurm 的已分配 CPU 包含暂停进程占着的配额，不等于正在运行的 CPU。RESOURCE_STATUS.json 逐事件保留分配与暂停数；后期可出现21个分配、3组暂停、实际18，不能把 REPORT 中前期20分配/2暂停的例子误读为全程分配最大20。原始响应窗口的短时超额仍按原报告披露，不抹除。

全部384条pilot已领取后，其他任务逐步占用了pilot释放的槽。专家128个固定状态已按预注册独立登记与预检，先 held 排队，见 HELD_EXPERT_QUEUE_CLARIFICATION.md/receipt。为避免专家等待全部其他任务结束，在15:11UTC将本轮正在计算的一核转给专家：先对经进程命令验证为本轮的pilot组发SIGSTOP，再release已排队专家；专家运行后恢复原持久监控，保存新暂停组和事件。没有同时多开一个实际CPU，没有丢弃在途轨迹、重跑unknown或变更数值程序。原始事件与队列见EXPERT_CPU_HANDOFF.json。

这一操作只调整同轮独立工作的CPU份额，不改变科学设计。专家不依赖能力门、不参与源动作选择；原advance.py仍等待专家作业并执行同一官方单进程merger。诊断、轨迹、终止与判断未改。额外暂存的Slurm配额不是额外实际运行的CPU。内存与每步计时的混合缓存/JIT/暂停限制仍见TIMING_LIMITATIONS.md。
