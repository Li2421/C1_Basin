# 共享C1优化器稳定性诊断（2026-09-18）

这是在Job41未通过局部脱困门槛后另立的有限开发诊断，不追溯改变该门槛。新增终末guard没有显示增益，故不接入本次训练。已有ordered风险在独立预测噪声实验有相关性，局部控制效果仍不稳定；本次旨在区分优化器是否使共享模型已有脱困能力反弹，不作为风险已解决的证明。

两组按顺序运行：Adam和无动量SGD，各恰好16更新，学习率均1e-4。均从旧C1的同一个selected-update64 checkpoint初始化（原文件哈希写入config），不是从零训练。沿用原ordered风险、epsilon=.01、lambda0=1、dual_lr=.1、batch8、原训练起点池均匀无放回采样；共同新训练RNG seed2026091842。每4更新验证，64个原开发起点各使用新噪声82551/82552。Safety仍为零残差。

保留完整 min J_def subject to E[R]<=epsilon、预更新风险的dual更新、双硬安全投影和原实值目标回溯；不作风险纯损失训练或逐样本动作拟合。SGD与Adam仅替换optax更新器；原回溯和拒绝回滚仍适用。SGD的学习率数值与Adam一致不等于有效步长一致，分析必须报告这个限制。SGD保持原性能而不改善风险不能算修复。

已有假设：零风险批次只优化J_def，Adam归一化或重启可能快速削弱残差；此前零风险批次J_def单步下降中位数约26%至30%，而其原始梯度很小。此为相关性线索，不是因果证明。本次比较固定验证曲线、最后更新、可行检查点、死锁及成功，不只挑最好一次均值。

`train_optimizer_diagnostic.py` 只加载train和development validation，不生成或加载预留test列表；无独立测试执行路径，无自动64更新延长。两组固定预算完成后停止，保存checkpoint、配置、history、validation与源码快照。Safety难度不足则拒绝正式对照；不通过筛样本提高难度。

四进程仅并行同批独立轨迹，按原顺序平均梯度。Slurm申请shard:1、4CPU、32GB、1小时，两个优化器顺序执行。旧checkpoint训练时的CBF状态误拒绝已在通用求解器数值修正中解决；本次两组用相同新版，原安全约束及容差不变。旧来源与当前来源不得混淆，数值修正证据见 `C1_CONDITIONAL_RISK_THEORY.md`。

即使本次找到验证可行模型，后续仍需完整训练、多训练种子、预先冻结的独立配对实验与合理扩展场景；不能把本次开发结果当作最终显著改善或泛化结论。
