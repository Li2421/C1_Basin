## 实际控制与训练路径

后续实验规模遵循用户最新要求：优先较小的场景、少量分批对照；不再默认启动原48组大场景队列。原协议与结果保留为历史证据，未完成项如实标注。新的比较需先明确场景大小、预计耗时和独立评测范围，再按新版本冻结；缩小场景不等于缩短评分窗口或更改死锁定义，也不取消配对评测、多种子确认及安全检查。GPU已恢复授权，必须通过Slurm申请。

    u_nominal = speed_bound(FlowBC_theta(observation, noise))
    u_safe    = hard_projection(u_nominal, physical_constraints)
    u_C1      = hard_projection(u_safe + G_phi(observation, u_safe), physical_constraints)
    x_next    = x + dt * u_C1

Flow-BC θ 冻结，仅优化物理残差 φ。安全约束来自环境几何、机器人尺寸和速度限制。相同状态、相同噪声下的 u_safe 是干预成本的参照；不是另跑一条 Safety 轨迹后做动作回归。C1 不读取专家的 mode、stage 或动作标签，不引入额外的路线图、退让控制器或几何势函数。

    J_def  = mean_episodes mean_actual_actions ||u_C1-u_safe||²
    J_live = mean_episodes R(trajectory)
    minimize J_def subject to J_live <= epsilon
    L = J_def + lambda * (J_live-epsilon)
    lambda_next = max(0, lambda + dual_lr * (J_live_before_step-epsilon))

当前 ε=0.01。Adam 与事务式回溯属于通用数值实现：同一批次、噪声和 λ 下重评实际 L，拒绝则回滚参数和优化器状态。若 Adam 方向不是下降方向，可重启动量再提议；没有新增场景相关目标或控制步骤。验证可行后按 J_def 最小选模。

## 风险公式与可证明的范围

本节后续先记载历史 smooth-sum 风险；9月18日正在验证的候选是 `ReLU(1+rho*exp(sign(rho)*s))`，rho为精确联合事件裕量，s为历史smooth-sum。其新增梯度路径、排序性质及未通过的开发门槛见 `C1_ORDERED_GUIDANCE_PROTOCOL.md`。候选尚未证明优化有效性，不应把本节历史实验结果归于新候选。

严格死锁 D 保留原环境的低速、低进展、未完成条件及持续计时。将原子谓词转换成“越大越接近满足死锁条件”的无量纲裕量 m。对每个完整持续窗口 w：

    q_w      = min_(t,j in w) m_(t,j)
    qtilde_w = -tau * log(mean_(t,j in w) exp(-m_(t,j)/tau))
    rho      = max_w q_w
    rhotilde = tau * log(sum_w exp(qtilde_w/tau))
    R_D      = ReLU(1+rhotilde)

τ=0.02。若每窗口含 L×M 个原子，K 为完整有效窗口数，则
`0 <= rhotilde-rho <= tau*log(L*M*K)`，且 `1_D <= R_D`。无完整有效窗口时风险为零。

终局停滞死锁 S 使用原六分类的 `stalled_deadlock`，仅适用于 timeout：最后 round(2/dt) 个动作后状态中，所有速度<0.05，每个机器人首末目标误差的绝对差<0.02。以这些原子裕量作同样的上近似 soft-min，得到终局风险 R_S；原事件非 timeout 时 R_S=0。于是

    R = R_D + R_S
    1_(D or S) <= R
    P(D or S) <= E[R]

这对应原检测定义下的死锁事件上界，不是校准概率。用和而非 max 聚合，以避免一项完全屏蔽另一项的梯度。公式及历史审计详见 [联合风险数学说明](C1_DEADLOCK_UNION_THEORY.md)。

总体 E[R]≤ε 才推出总体概率界。有限验证均值≤ε 不自动证明总体约束；独立结果与不确定性必须另外报告。离散终止与 timeout 门控停止求导，AD 给出固定事件分支内的路径导数，不能宣称其为事件概率梯度的无偏估计，也没有神经优化全局收敛证明。

普通 timeout 可以得到零风险，例如持续运动却未到目标。因此当前目标函数不保证所有任务最终完成：若某个冻结基线同时 J_def=0、R=0 却不成功，仅此优化目标不会强迫它改变。必须独立检查死锁是否转为成功，不能只看风险下降或死锁标签消失。

完整轨迹的事件上界也不意味着 20 秒前缀能预测未来。既有开发审计中，20 秒前缀对后续严格死锁的 AUC 接近 0.5；目前没有“20 秒足够”的证据。完整 first-event 轨迹支持当前训练和评分。
