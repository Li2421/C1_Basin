# 2026-11-10 系统盘产物迁移

用户授权尽可能迁移系统盘内容，以不影响实验为前提，并要求记录文档。

## 范围与执行方法

本轮优先选择 diagnostics 下不含代码、Git 跟踪文件、硬链接、软链接及最近一小时写入的纯数据目录，以及共享 rollout 的 JSONL journals。保留代码、环境、配置所在的混合目录；SQLite 主库和 WAL/SHM 暂留原处。常用产物迁到 /mnt/ssd/zhihan/Basin_C1/ 相同相对路径，原路径用软链接保持兼容。pip 缓存单独迁移；uv 缓存因与环境存在硬链接暂保留。回收站保留，避免未经分类改变其恢复语义。

脚本 scripts/migrate_storage_20261110.py 基于已使用的 migrate_result_directories.py，增加 JSONL/NPY/PT/PTH/MP4 数据格式、SSD 挂载检查和限定为 pip 缓存的任意普通文件模式。拒绝特殊文件、链接、正在打开的目录和近期写入。复制后逐文件比对 SHA256、完整目录项、大小、模式和时间戳，并确认源未变化；sync 落盘后原子交换为软链接，再移除已验证的 home 副本。未通过验证保留源，不删除研究证据。

迁移脚本、计划和本文在切换前提交并推送到独立 maintenance/storage-20261110 分支，避免混入当前研究工作区未提交修改。迁移不等于独立备份，不更改实验控制器、配置、执行语义、训练或 rollout 结果。

## 审计和恢复

详细清单与逐文件 SHA256 位于 /mnt/ssd/zhihan/Basin_C1/audits/storage_20261110/；只以每目录 summary.json 的 complete 状态认定完成。执行日志和退出码保存在该目录，进程独立于终端运行。

恢复时先停止相关读写，把 SSD 目录复制到 home 同级临时目录，逐文件校验并确认空间足够，再以临时目录替换原软链接；恢复验收前保留 SSD 副本。数据盘必须保持挂载，后续实验仍遵守 AGENTS.md 的输出路径预检规则。

## 验收

执行完成后补充准确数量、释放空间、跳过项与验证结果。

## SQLite 补充迁移条件

另使用 scripts/migrate_sqlite_20261110.py 处理共享库：仅在无进程打开共享目录、三个文件均为普通文件且 WAL 为零字节时运行；复制主库/WAL/SHM 到 SSD 的 database 子目录，逐文件 SHA256 比对、源稳定性检查及 SQLite quick_check 通过后才切换三个原路径。用原路径建立只读连接验收，并再次核对主库哈希。SHM 是可变共享内存文件，只读连接也可能更新它；其复制前一致性单独留证。条件不满足保留原库。此补充取代前述暂留 SQLite 的初步安排。
