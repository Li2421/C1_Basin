# 二、场景生成器（全部写在本轮目录，不改 `bottleneck_family/` 的任何文件）

**实现方式：** `bottleneck_family` 的原接口有两个限制，本轮必须用子类绕开，不得改原代码：
- `Config.__post_init__` 要求至少 1 道带开口的隔墙；
- `build_instance` 按 Gap 的左右两侧待命位放置默认机器人，十字路口、环岛、房间、随机障碍场会因此报错。

做法：
- 在本轮目录写 `GeneratedGeometry(Geometry)`：由外边界加一组轴对齐矩形（隔墙也表示为矩形）构造 `walls` 与 `rectangles`。`valid_points`、`visible`、`path` 的算法逐字继承，不改。
- 写 `GeneratedEnv(BottleneckEnv)`：只重写 `__init__`，接受预先构造好的几何、起点与目标；`reset`、`snapshot`、`step`、碰撞与终止判定全部继承，不改。
- **等价性单元测试：** 对 Gap 单门配置，用同一组矩形构造的 `GeneratedEnv` 与原 `BottleneckEnv` 的 `walls` 逐元素相同（含顺序）；在同一起点、目标与动作序列下，两者的轨迹、碰撞与终止逐位一致。不一致就停下整轮并报告。

**补充决定（用户 2026-10-17，解决单机器人接口冲突）：**
- 原 `Config` 拒绝少于 2 个机器人，继承的 `step()` 也无法处理没有机器人对的情况。允许在本轮目录另写**单机器人专用环境** `SingleAgentGeneratedEnv`，**只用于**示范采集与导航能力门。所有多机器人实验（能力门、探测、评估）仍然只用 `GeneratedEnv`，并完全继承原 `step()`。

- 目标族的任何标签都不得进入训练、验证或预处理。

**训练族数量的规模曲线（核心假设）：**
- 对每个目标族，从其余 5 族中按预注册的固定随机顺序取 m ∈ {0, 1, 3, 5} 族（m = 0 表示只用已有场景），加上已有场景训练，记录目标族上的遗憾；
- 每个 m 取 3 种不同的族组合（m = 5 只有 1 种），组合在预注册中写死。

**锁定测试（族 G）：**
- 在族 A–F 的全部分析完成并冻结之后，用族 A–F 全部标签加已有场景训练最终模型，冻结并留收据，再打开族 G 的评估标签。
- 族 G 只评估一次，不得据此调整任何设置。

**对照：**
- 源场景平均最佳臂：训练数据中平均成功率最高的臂；
- 一律 η13 → η10 按比例切换；一律全程 η10；
- 少量标签选择：在目标族的 pilot state 上，每臂取 k ∈ {1, 2, 4, 8, 16} 条标签，按 round34 `fewshot.py` 的方法选择，随机种子写入预注册；另报 round38 的"4 个 pilot state 上比较时间表与持续右手规则"的简化版本；
- 目标族 oracle：交叉拟合（按 state 奇偶分半）与样本内两种。

所有选择都在打开对应目标族的评估标签之前冻结并留收据。

# 七、预注册的终点与判定

| 编号 | 检验内容 | 判定标准 |
|---|---|---|
| 多场景终点 1（主） | 学多类场景后，零样本选择是否优于简单对照 | 族 A–F 合并（留一族），选择模型的平均遗憾低于源场景平均最佳臂，配对 CI 上界 < 0 |
| 多场景终点 2 | 实用标准 | 族 A–F 中，选择模型遗憾 ≤ 5pp 的目标族数 ≥ 4 |
| 多场景终点 3 | 训练族越多越准（核心假设） | 遗憾对 m 的回归斜率 < 0：在目标族与组合两层成簇重抽，95% CI 上界 < 0 |
| 多场景终点 4 | 锁定测试 | 族 G 上：(a) 最终模型的遗憾 ≤ 5pp；(b) 最终模型所选臂 − safety baseline 的配对 CI 下界 > 0 |
| 多场景终点 5（描述性） | 修正在各类场景中的作用与偏好 | 每族：最佳修正臂 − safety baseline（死锁修复的成功率提升）；获胜的臂族；时间表 − 最佳固定 η；持续右手规则 − 时间表；nominal only → safety baseline 的转移表；五层证据表；少量标签曲线 |

**证据等级：** 族 A–G 的标签全新，选择先于标签冻结，多场景终点 1–4 标为 CONFIRMATORY；已有场景的标签保持原有等级。

# 八、结论映射

| 观察结果 | 结论 |
|---|---|
| 多场景终点 1、2、4 都通过 | 学习足够多的场景之后，可以零样本预测新类场景的修正 |
| 多场景终点 3 通过，终点 2 不通过 | 方向正确：场景越多越准，但目前的场景数量还不够；报告外推所需的场景数 |
| 多场景终点 1 不通过，少量标签曲线在 k ≤ 4 时达标 | 零样本跨场景仍不可行，方法应写为"少量标签选择" |
| 终点 5 中修正在每族都显著提升成功率 | 即使选择不能零样本跨场景，"安全层 + 修正"在各类场景都能修复死锁 |
| 多数族的实例未通过多机器人能力门 | 瓶颈在 controller 本身，如实报告，不计入方法结论 |

# 九、执行顺序与阶段门

1. 完整性审计（开始）→ 复现门（round36 的 16 条）→ 生成器与单元测试 → 有效性检查与几何清单 → 预注册与收据。
2. 示范采集 → 行为克隆训练（GPU）→ 导航能力门。
3. pilot 与多机器人能力门 → 探测。
4. 族 A–F 评估标签 → 留一族与规模曲线的全部选择冻结（这一步在打开对应目标族标签之前完成）→ 分析。
5. 冻结最终模型 → 族 G 评估 → 锁定测试分析。
6. 完整性审计（结束）→ 交付。

任何阶段被挡住时，把受影响的族记为缺口并写明原因，继续其余族。只有源码保护或 DB 规则无法满足时才整体停下。
