## 一、为什么要做这一轮

v2 的开发目标 G1–G3 不能说明"学到了"。在 v1 已有标签上可以直接算出：
- 一个完全不学习、所有场景都用 η-A 的方法，在 11 个去重场景留一场景时比"所有场景一组 η（训练场景里最好）"高 +3.11 个百分点，没有任何场景变差，满足 G1；留一族与 18 场景的这一对照本身几乎都是 η-A，G2、G3 也满足。
- 原因：留出一个场景后，训练平均会翻向对该场景更差的那组（下面 L1 的统计量在这一对照上为 −3.34 个百分点），所以这个对照被留一法系统性压低。
- 用成功率直接比较，11 个场景能以 80% 把握检出的差约为 7–8 个百分点（按场景近邻选 η 减固定 η-A 的自助法标准误 2.97 个百分点；v1 critic 对整个场景平均后的选择减固定 η-A 为 2.44）；而整个场景选一组 η 最多也只比固定 η-A 好约 5（诚实估计）到 10（样本内乐观）个百分点。

因此本轮把"学到没有"与"有没有用"分开检验。

## 二、检验（全部零 rollout）

成功率一律用 `cross_scene_correction_v1/LABEL_TABLES.json` 的 49 个旧候选标签（种子 0，unknown 计失败，场景内控制器类型等权、状态等权）；只看 11 个去重场景的留一场景折，另报留一族折。

**L1 学到没有（场景对号检验）：** 对一种"每个留出场景只选一组 η（49 个旧候选之一）"的方法，令 R[T, S] = 为场景 S 选出的 η 在场景 T 上的成功率。统计量 D = 各场景 R[T, T] 的平均 − 各场景"别的场景的选择在本场景上"R[T, S≠T] 平均值的平均。零假设下把"选择"随机重新分配给场景：11 个场景用 20,000 次随机排列（`numpy.random.default_rng(2026102521)`），8 个场景子集用全部 8! 种排列精确计算；单侧 p = 排列后对角平均 ≥ 实际对角平均的比例。D > 0 且 p 小，说明为某个场景做的选择确实更适合这个场景，也就是读懂了场景。
- **主检验：** v2·不退回（`v2_49_no_fallback`），11 个场景。它是 critic 自己的按场景选择，不受退回规则强制。
- **辅检验：** v2·只在 49 个旧候选里选（`v2_49`），只在 v2 没有退回的 8 个场景上（拥挤随机、八机静态障碍、对穿 4 机、对穿 8 机加密、缺口 4 机、缺口 6 机、双瓶颈、错位口；以 v2 `GUARD.json` 为准）。
- 同样报告：v2·无先验、v2·原始场景描述、v2·修正不收缩、v2·通用输入版本（L2）。
- **对照（检验本身是否灵敏，期望值来自 v1 数据；对不上只报告，不停）：**

| 选择来源 | 11 个场景：D（个百分点），p | 8 个场景：D，p（精确） |
|---|---|---|
| 按场景近邻选 η（v1 冻结） | +6.21，约 0.005 | +5.49，0.0167 |
| v1 critic 对整个场景平均后的选择 | +10.44，约 0.012 | +7.90，0.0804 |
| v1 不看控制器的 critic，同上 | +12.38，约 0.003 | +3.93，0.0804 |
| 所有场景一组 η（训练场景里最好） | −3.34 | −2.64 |
| 固定 η-A | 0，p = 1 | 0，p = 1 |
| 每个场景样本内最佳（乐观上界） | +17.85，< 0.001 | +10.80，0.0003 |

v1 critic 的那两行算法：v1 `folds/loso__<场景>/CHOICES.json` 中 `full_logits`（或 `no_controller_logits`）前 49 列取 sigmoid，对全部控制器与状态平均后取最高者。

**L2 读没读留出场景（v2·通用输入版本）：** 用同一个冻结的完整 critic、同一先验与同一 λ，把留出场景的 c′ 换成该折训练场景 c′ 的平均，把每个状态的 h 换成该折训练场景全部状态 h 的平均（控制器不变、不退回），整个场景选一组 η（49 个旧候选内）。报告：真实描述与通用描述选择不同的场景数；两者成功率之差（逐场景，以及场景等权平均与成对自助法区间：5000 次，场景 → 控制器类型 → 状态，`numpy.random.default_rng(2026102522)`）；通用输入版本的 L1 统计量。真实描述的 D 减通用输入的 D，就是"读场景"本身带来的部分（通用输入版本已经包含了各折训练集不同造成的差异）。

**L3 有没有用（对最强的固定 η）：** 学习选 η v2 减固定 η-A；v2·只在 49 个旧候选里选减固定 η-A。分别在 11 个场景与 8 个不退回场景上报差值与区间（v2 的成对自助法，读 v2 交付的逐格结果，主方法含生成器提案的新 rollout 结果）。同表列出"一直用 η-A"减"所有场景一组 η（训练场景里最好）"（期望 +3.11），作为"不学习也能达到的数"。

**L4 修正能否在训练场景之间迁移：** 读 v2 每折 `LAMBDA_SELECTION.json`：所选 λ，以及内部留一时各 λ 相对 λ = 0 的平均成功率增益。

**L5 生成器学到没有：** 对每个留一场景折的留出场景、每个状态，正例 = 该状态上类型等权成功率达到 49 个候选中最大值的候选（最大值为 0 的状态不计）。用 v2 冻结的生成器（`folds/<折>/generator/SELECTED.json` 所指的检查点，`networks.log_prob`），比较真实输入与通用输入（同 L2 的平均 c′ 与平均 h）下正例的平均对数密度，取差值；状态等权、场景等权；成对自助法（场景 → 状态，5000 次，`numpy.random.default_rng(2026102523)`）。超出范围的场景单列。

## 三、判读规则（预先写定）

- **学到了，而且有用：** L1 主检验 p < 0.05，真实描述的 D 大于通用输入版本的 D，且 L3 中学习选 η v2 减固定 η-A 的点估计 > 0。区间下界 > 0 才写"可分辨"，否则写"方向为正，11 个场景分辨不了"。
- **学到了场景相关的东西，但没有比固定 η-A 好：** L1 主检验 p < 0.05，L3 点估计 ≤ 0。
- **没学到场景相关的东西：** L1 主检验 p ≥ 0.05。此时 v2 相对"所有场景一组 η（训练场景里最好）"的任何提高，只能归于通用修正（对所有场景一样的偏好改变）或留一法造成的对照偏低，不能算学到。
- L1 辅检验、L4、L5 照报，不改变上面的判读；但若 L4 中留一场景折有 8 折以上 λ = 0，另写一句"修正没有学到能在训练场景之间迁移的东西"。
- 一律读未四舍五入的 JSON 数值。
