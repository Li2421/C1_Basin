# 五、第一阶段：单积分器下的改动

## 5.1 分布式安全投影：按各论文的责任分配

每台机器人只求自己的二维速度，目标是 min ‖u_i − u_nom,i‖²，约束里只出现自己的速度。

配对约束统一写成 2(p_i − p_j)·u_i ≥ −c·γ·h_ij，其中 h_ij = ‖p_i − p_j‖² − d_safe²。d_safe 与 γ 沿用 v1 的 `HardProjectionConfig` 默认值和场景 config。责任系数 c 按场景定：

| 场景 | 责任分配 | c | 依据 |
|---|---|---|---|
| 窄通道场景、二维拥挤随机场景 | 互惠：各承担一半 | 1/2 | IMPC-DR 式 (5)–(6)，两台机器人各自留在中点以外的半空间 |
| 圆形围场五机随机场景 | 主线为去中心化互惠（式 16）；第二优先级为去中心化全责（式 15） | 1/2；1 | Jankovic 等 |
| 门口场景 | 全责，对方视为当前位置的静止障碍 | 1 | mpc-cbf `main.py` |

- **邻居信息：** 每台机器人使用其他全部机器人的当前位置（同步测量，不限感知半径）。不使用别人的名义输入或安全速度，不交换投影结果。
- **墙约束：** 每台机器人全责，墙线段与参数与 v1 相同。
- **门口场景的半径：** 原代码把对方当作半径 0.02 的小圆，会允许物理碰撞。流程版改用真实半径（与 v1 相同的 d_safe），作为声明偏差写入 `PARAMETERS.md`。
- **不加任何补救：** 不加松弛、优先级、回退策略或步后修正，数值重试只用原有的同问题重试。单积分器下 h ≥ 0 时 u_i = 0 恒可行；若仍出现无解或数值失败，记为 unknown，不改约束。
- **预期差异：** 已到达的机器人因为到达停止而名义速度为零，在分布式下只在自身约束要求时才会移动。窄通道场景的挡路机器人不再被推开，这是本轮要测的差异，不是错误。
- **`THEORY_CONDITIONS.md` 中写出：**
  - c = 1/2 时，两台机器人各自的约束相加，恰好推出 v1 的联合约束。
  - c = 1 时，相加得到的是系数为 2γ 的联合约束，采样保持下的安全条件变为 2γΔt ≤ 1，逐场景检查。
- **单元测试：**
  - N = 1 时与集中式逐位一致；
  - 配对约束的代数正确；
  - 交换机器人编号，结果不变；
  - 碰撞判定与 v1 完全相同。

## 5.5 死锁判据：改为逐机器人

在 v1 的互斥分类基础上，把 4a 改为逐机器人。

**机器人 i 的锥残差：** 取 i 自己的投影中起作用的约束行；集中式时取联合起作用行在机器人 i 速度块上的分量。残差为 min over μ ≥ 0 of ‖u_nom,i + Σ μ_k a_k‖ / ‖u_nom,i‖。

**4a′ 机器人间滤波器平衡点死锁：** 在最后 W 步中至少 90% 的步上，同时满足：
- 机器人 i 静止；
- 名义输入非零；
- 被投影改写；
- 逐机器人锥残差 < τ；
- 起作用的行中至少有一条是与其他机器人的配对约束。

**4a″ 墙前平衡点：** 条件同上，但起作用的行只有墙约束。这是局部陷阱，不计为机器人间死锁。

**其余规则：**
- 4b 至 5 类与 v1 相同；W 与 τ 的敏感性网格与 v1 相同。
- v1 的联合锥残差判据也照算一份。两种判据在两种安全层下都要报告。

  - 速度上限写成一条一阶约束。
  - 二次规划无解时，照 Jankovic 第四节取最不违反的解，逐步记录为"约束违反"事件，不记为 unknown。
- **独轮车：** 每台机器人用离散控制障碍函数 h(x_{k+1}) ≥ (1 − 0.1)·h(x_k)，即 mpc-cbf 的 `get_cbf_constraints`。对方视为当前位置的静止障碍，用真实半径，在前视点坐标下解一步问题。

**修正：** 加在期望速度上，再经过跟踪层和同一安全层。修正基中的"安全速度"取第一次安全层输出对应的下一步速度。

**死锁判据：** 按 5.5 的同样定义，双积分器在加速度层计算，门口场景在前视点速度层计算。另报一条直接判据："速度接近零且位置不再变化"。

**范围：**
- 只做只加安全投影与三种固定修正，只跑合格 controller，不做场景内重新学习。
- state：窄通道场景与门口场景 64 组，二维拥挤随机场景 112 组，圆形围场五机随机场景 16 组。

**归因：** 与第一阶段比较时，差异只能归因于动力学；与 v1 比较时，要写明"动力学与安全层同时不同"。

# 七、第一阶段的实验与比较

## 7.1 要跑的

| 安全层 | 场景 | 做法 |
|---|---|---|
| 分布式 | 四个场景 | 只加安全投影：全部 48 个实例加白盒参照；三种固定修正：合格实例；场景内重新学习：见 7.4 |
| 集中式 | 二维拥挤随机场景（新 state，去掉墙后必须重跑）、圆形围场五机随机场景（16 组主 state，v1 已完成的部分按精确身份复用） | 只加安全投影、三种固定修正 |
| 集中式 | 窄通道场景、门口场景 | 全部按精确身份复用 v1，不重跑 |
| 无安全层 | 二维拥挤随机场景的新 state | 名义直接执行，作背景，非主线 |

- seed 取 0–1。
- 圆形围场的去中心化全责版本（c = 1）只跑只加安全投影与全程 η10，作为第二优先级。

## 7.2 失败拆分

- 按 5.5 分类。
- "controller 级失败"单独列出：在某个场景、某种安全层下，只加安全投影时全部 state 的成功率 ≤ 5% 的合格实例。
- 这些实例照常计入总体，另报去掉它们之后的结果。它们不得作为死锁证据。

## 7.3 场景区分度

每个场景、每种安全层报告两个数：
- 合格实例中，只加安全投影的成功率落在 (5%, 95%) 之间的实例数，称为"状态相关失败"；
- 至少在一个 state 上出现 4a′ 的实例数。

若某个场景在分布式下所有合格实例仍 ≥ 98%，照 v1 的规则只做固定修正。

## 7.4 场景内重新学习（分布式）

- **动作菜单：** 照 v1 的 L3，用 `LEARNING_MENU.json` 中已封存的同一 12 个动作，在分布式安全层与逐机器人修正下执行。
- **state 划分：** 窄通道场景与门口场景沿用 v1 的 `LEARNING_SPLIT_<scene>.json`；二维拥挤随机场景与圆形围场五机随机场景见 5.2、5.3。
- **标签：** 每类前 2 个实例 × 训练 state × 12 个动作 × seed 0。
- **模型：** 模型与留一类型交叉验证照 v1 的 `learn_critic.py`。
- **冻结与评估：** 冻结后在评估 state 上选动作，选择在第一条评估 rollout 提交前密封。
- **冻结流程零样本：** 照 v1 的结论记为不适用，不再尝试。

## 7.5 比较与统计

- 每个场景单独报告，再报四个场景合并（类型等权）。
- **分布式内部：** 各种修正相对只加安全投影的成功率差；场景内重新学习减最佳固定修正。
- **集中式对分布式：** 同一 controller、state、seed 配对，比较以下两项：
  - 只加安全投影与每种固定修正各自的差；
  - "修正增益之差" = (分布式修正 − 分布式只加安全投影) − (集中式修正 − 集中式只加安全投影)。
- **另报：** 碰撞率、超时率、unknown、伤害数，以及 4a′ 与 4a″ 的比率。
- **统计方法照 v1：** 5000 次配对 bootstrap，按类型 → controller → state 成簇，同一 state 的两个 seed 同簇。unknown 按下界计，另报上界。

# 九、失败处理与无人值守

| 类别 | 包括 | 处理 |
|---|---|---|
| 整体停下 | 写入了只读位置；共享数据库规则被破坏；分布式安全层不改已有代码就无法实现 | 停下报告。只有这三种情况可以整体停下 |
| 主线 | 第一阶段的全部内容 | 作业失败先读日志。基础设施原因（节点故障、内存不足、Slurm 时限、被抢占）：未完成的部分按写定的案例与种子重新提交。实现错误：修正后只重跑受影响的部分，写进迭代日志。某个场景或类型确实做不了：记为缺口并写明原因，其余继续 |
| 非主线 | 第二阶段、圆形围场全责版本、逐机器人进度切换、无安全层背景、图 | 不得作为主线的前置条件。数值先写入 JSON/CSV 并封存，图最后单独生成。失败记入 `GAPS.md`，其余照常 |

- 协调器自己执行上表。运行期间至少每 30 分钟更新一次 `STATUS.md`（当前阶段、已完成量、阻塞原因、已采取的处理），并查看 `squeue`。只要还有不依赖受阻部分的工作，就继续做。
- 资源被 v1 占满时，先做不需要 rollout 的部分（复制、单元测试、preflight、v1 集中式轨迹的判据重算），等资源释放后再提交。
