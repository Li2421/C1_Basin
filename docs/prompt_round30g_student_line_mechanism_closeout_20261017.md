# 三、分析定义（计算任何结果之前写入预注册，附 UTC 与 sha256 收据）

**1. 绕行方向：** 沿用 `ring_exchange/expert.py` 中 `circulation_signature` 的规则。
- 对每个机器人，计算它绕中心的累计角位移（逐步展开）：大于 0.15 rad 记为逆时针，小于 −0.15 rad 记为顺时针，其余记为未绕行。
- 全队标签：
  - 所有绕行的机器人同向，记为"一致"；
  - 既有顺时针又有逆时针，记为"不一致"；
  - 都未绕行，记为"静止"。
- 除整局外，还要在第 100、200、300 步计算同样的标签，用来看方向在什么时候定下来。

**2. 失败类型：**
- 碰撞：按碰撞时刻的位置判定是机器人与机器人相撞，还是与中心障碍或外环相撞。
- 超时：记录最后一次取得进展的时刻（全队到目标的总距离最后一次下降 ≥ 0.05 m 的时刻）、超时时仍未到达的机器人数，以及未到达的机器人之间是否存在"相向且绕行方向相反"的一对。

**3. 停滞段：** 沿用 round28 的定义：速度低于 0.01 m/s、未到达目标、且连续至少 40 步。另外按用户的问题，统计"在动但没有进展"的时长：速度不低，但 2 s 内到目标的距离减少不足 0.05 m。

**4. 配对比较：** 同一 controller、同一 state、同一 seed 下，在不同臂之间比较绕行标签与失败类型，例如只加安全层与加时间表。

**5. CI：** 先在 controller 层重抽，再在 state 层成簇重抽，共 5000 次。标签此前都已打开，全部结论为 DEVELOPMENT。
