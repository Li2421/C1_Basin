# 一、背景与问题

**论文定位（用户 2026-10-16 确定）：** 修正黑盒 controller 在安全层下产生的死锁。
- **黑盒：** 方法不依赖 controller 已知的控制律公式，只允许探测它的行为。学习得到的模型、模型预测控制、A* 一类规划器都算黑盒。
- **白盒（不在主线范围内）：** 直奔目标、势场这类手写的闭式规则。
- 任何原因导致的死锁都在范围内；安全层是设定，不是假定的成因。

**分布式这条线的已有结论：**
- **round30 至 round30c：** 14 个不通信的分布式一步学生，是从联合 MACFlow 蒸馏得到的黑盒学习型 controller。
  - 只加安全层：11.8%；
  - 加上集中式确定的"前 500 步 η13、之后 η10 的时间表"：94.2%；
  - 公平调参的右手规则：11.3%。
- **round30d：** 只靠修正、不用学习型 controller 时只有 28.1%，说明修正与学习型 controller 是协同的。

**本轮问题：** 结论是否只对蒸馏学生成立？换成其他黑盒 controller 族，在同样的分布式安全层下：
1. 会不会产生死锁或停滞；
2. 在集中式下确定的 η（以及它的时间表）能否不经调整就修好它们；
3. 公平调参的右手规则能否做到；
4. 冻结的通用 critic 能否零样本选对。

# 四、预注册的终点与判定

每个 controller 族分别判定。CI 先在 controller 层重抽，再在 state 层成簇重抽，共 5000 次，使用配对比较。unknown 按下界计，另报上界。

| 终点 | 检验内容 | 判定标准 |
|---|---|---|
| 终点一 | 安全层下是否出现死锁或停滞，修正能否修好 | "前 500 步 η13、之后 η10 的时间表"减去"只加安全层"，CI 下界 > 0 |
| 终点二 | 是否优于公平调参的右手规则 | 该时间表减去公平调参的右手规则，CI 下界 > 0 |
| 终点三（描述性） | 冻结 critic 能否零样本选对 | 冻结的通用 critic 相对四个修正臂中事后最优者的平均遗憾；与一律用该时间表、一律全程 η10 的配对差 |
| 终点四（描述性） | 失败来源 | 从"只跑 controller"到"只加安全层"的逐条转移表；失败拆成"自身停滞"（不加安全层也超时且无碰撞）与"安全层导致的停滞"（原本碰撞、加安全层后超时），以及每类被各臂救回的数量 |

**失败机制指标（描述性）：** 沿用 round30g（`diagnostics/teacher_student_line_closeout_v1/`）预注册的定义与分析代码。代码复制到本轮目录，只改路径。每个 controller 族分别报告：
- 碰撞对象：撞中心障碍、撞外环，还是机器人之间；
- 全队绕行方向标签：一致、不一致、静止；
- 超时局里"在动但没有进展"的时长、严格低速停滞段、最后一次取得进展的时刻、未到达的机器人数；
- 修正相对只加安全层，在前 100 步多取得的进展。

round30g 发现，学生与教师在安全层下的失败，主要是靠近障碍与外环时"在动但不前进"，机器人之间互相顶死的很少。本轮要检查其他黑盒 controller 族是否也是这样。

# 五、结论映射

| 观察结果 | 结论 |
|---|---|
| 三个族的终点一、二都通过 | 集中式确定的修正，能不经调整地修好多类分布式黑盒 controller 的死锁，并优于公平调参的右手规则。结论不限于蒸馏学生 |
| 某族在安全层下没有死锁问题（两个臂都高于 98%） | 如实报告：该类 controller 自身就能处理交互，修正对它不必要 |
| 某族终点一通过、终点二不通过 | 对该族，经典的右手规则调好后同样有效；需要说明我们的优势只在于不用逐族调参 |
| 某族终点一不通过 | 修正对该族无效，报告失败类型与发生时间，作为方法的边界 |
| 冻结 critic 在某族上系统性选错 | 与蒸馏学生的情况一致：零样本时优先使用稳健的默认时间表 |
