# 三、设计（先写 PREREGISTRATION.md，附 UTC 时间与 sha256 收据）

**单元：** 每个“场景（或变体）× 算子”为一个单元，共 30 个。

**划分：** 每个单元按 state_uid 排序，前 20 个 state 作为校准池，后 20 个作为评估集。两者不重叠，所有 seed 都使用。

**菜单：**
- 主菜单 M：{F10、F15、S13→10@3H/7、S15→10@5H/7}。根据 round20 的教训，这里包含了 F10。
- 次菜单：全部 7 个臂。

**模拟：**
- 对每个 k ∈ {1, 2, 4, 8, 16}，从校准池中为每个臂无放回地抽 k 条 episode（state 与 seed 的组合）。每个 k 重复 1000 次，随机种子写入预注册。

**方法：**

| 代号 | 方法 |
|---|---|
| D0 | 不试跑，固定选源平均臂 S15→10@5H/7（即 k = 0） |
| E | 选校准样本中经验成功率最高的臂；并列时取 D0 |
| S（安全） | 默认选 D0 的臂；只有当某个臂优于 D0 的后验概率 ≥ 0.9 时才切换（Beta(1, 1) 先验）；若有多个臂满足，取后验均值最高者 |
| SE（逐步淘汰，次要） | 每轮淘汰明显较差的臂，总预算相同 |

**评估：** 用评估集上各臂的成功率计算遗憾，参照为评估集上菜单内的最佳臂。

# 四、预注册指标与判定

**指标（每个单元、每个 k、每种方法）：**
- 平均遗憾；
- 遗憾的 90% 分位；
- P(遗憾 ≤ 3pp)，以及选中 oracle 臂的概率。

**k\*：** 使全部 30 个单元都满足 P(遗憾 ≤ 3pp) ≥ 0.9 的最小 k。对应的总试跑数为 4k（主菜单有 4 个臂）。

**判定：**

| 编号 | 检验内容 | 判定标准 |
|---|---|---|
| F1（主） | 少样本是否便宜 | 方法 S 的 k\* ≤ 8，即总共 ≤ 32 条有标签 episode |
| F2 | 是否安全 | 方法 S 在所有单元、所有 k 上，遗憾的 90% 分位 ≤ 10pp |
| F3 | 对照 | 与 D0 相比，S 在 k\* 时的平均遗憾更低，按单元配对 bootstrap 的 CI 上界 < 0 |

**描述性对比：** 与 Ring 上 controller 轴的少样本结果（round8：需要 128 条标签）对比，并解释差异（场景间的效应量更大）。
