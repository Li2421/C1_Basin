跨type4 的结论（第二节）指出两个问题，本轮同时处理：

1. **后期 η 的提议不够好。** 差距主要来自前后两个 η，而不是切换时间；在会卡的类型上，冻结生成器 8 个提议构成的 56 对里平均只有约 24% 能成功，Transformer 行为克隆策略上连每个 state 样本内最好的一对（81.2%）都低于人定双 η·按进度切换（97.9%）。本轮新增两种 η 来源：

## 4.2 时间表生成器

- **结构：** 沿用冻结生成器的对角压缩高斯与同一 η 盒，输出维度为 3 + 3（前期 η、后期 η）；输入为 state 的 100 维 `conditioning.flat` 与 33 维环境描述，加 controller 的 24 维机制特征。前期 η 的部分可以用冻结生成器的权重初始化。

- **训练目标：** 与冻结生成器相同：正例的负对数似然，加 0.25 的同 state 正负例排序项。
- **每折单独训练：** 留一类型的每一折只用源类型数据；checkpoint 用源类型内部的留一类型（嵌套）按留出正例负对数似然选。seed 41（与冻结生成器相同）。

## 4.3 切换时重查

前期 η 取自该 state 的 8 个冻结提议；切换方式为 {第 500 步, 按进度}；后期 η 在切换时刻重查。即每个 state 16 个候选（对角元不适用）。每个 (controller, 训练 state) seed 0 新增 4 个重查动作：前期 η 按种子从 8 个冻结提议中抽 2 个，× 两种切换方式。critic 的动作编码中，重查动作的后期 η 一栏填开局冻结提议中的均值，并加一个"切换时重查"指示位（共 14 维）。

## 4.4 覆盖比较（在覆盖子集上，开发证据）

覆盖子集的每个 (controller, state) seed 0 跑：时间表生成器的 9 对 × 按进度切换（用不含该 controller 所属类型的那一折的时间表生成器）、切换时重查的 8 个前期 η × 按进度切换。然后比较三种来源：

| 指标 | 定义 |

| 同数量样本内最佳 | 每个 state 从冻结提议对中按种子随机取 9 对（重复 200 次取平均）与时间表生成器的 9 对比较"取到的最好一对是否成功"；切换时重查的 8 个与冻结提议对中随机 8 对比较 |

# 五、两步决定：先判修不修，再选 η

## 5.1 critic

复制跨type4 的 critic，动作编码扩为 14 维（跨type4 的 13 维加"切换时重查"指示位），其余结构、损失、优化器、seed 17 / 23 / 41 集成、"完整分支与不看 controller 的分支按概率加权"的结构与选择规则不变；预处理、checkpoint 与权重只用源类型内部的留一类型（嵌套）来选。训练数据为已有 34 个动作、探索动作与重查动作的标签。时间表生成器提议对不另外标训练标签，由 critic 在动作空间中插值打分；它在覆盖子集上的排序准确率另报。

**补齐不修正的第二个 seed：** 只加安全投影在 48 个训练 state 上缺 seed 1 的 controller，补跑 seed 1，减少"修不修只差几个百分点"时的标签噪声。

## 5.2 critic 判修不修

对每个 (controller, state)：设 μ₀ 为 critic 对 (0, 0) 的集成均值，μ* 与 σ* 为修正候选中集成均值最高者的集成均值与集成标准差。**当且仅当 μ* − k · σ* ≥ μ₀ + δ 时修正**，否则执行只加安全投影。k ∈ {0, 1, 2}、δ ∈ {0, 0.02, 0.05} 只用源类型内部的留一类型（嵌套）选：目标为源内留出类型上选中动作的成功率（只在已标出动作上评分；未标出的选中动作按 critic 的预测不计分，计入"未评分比例"并报告）。选定的 (k, δ) 写进冻结记录。

## 5.3 探测规则判修不修（对照）

只用 24 维机制特征中只加安全投影探测臂的特征（第 300 步进度、冻结比例、在动但不前进比例）。规则形式："只加安全投影探测臂第 300 步平均进度 ≥ τ 且冻结比例 ≤ ρ 时不修正"；τ、ρ 在源类型上用同样的嵌套方法从开工时写定的网格中选。跨type3 记录的缺失特征向量照原规则填充并注明。

## 5.4 第二步：选 η

若判定修正，在修正候选（第零节"本轮主方法"中的候选池）中取 critic 集成均值最高者；并列规则沿用跨type4。

# 六、开发检验与冻结

**留一类型检验（训练 state，19 折）：** 每折留出一个类型，只在已标出动作上打分。报告：
- 判修不修的准确率：以留出类型上只加安全投影的 seed 0–1 成功率是否 ≥ 修正动作中已标出的最佳者为"应不修"，报告两种判修不修规则的混淆矩阵；
- 选中的已标出动作的成功率、未评分比例；
- 四种排序准确率（同跨type4）与"含 η = 0 的动作与其余动作之间"的排序准确率；
- 时间表生成器的留出正例负对数似然曲线。

**冻结：** 19 个留一类型折的时间表生成器、critic 与 (k, δ)、(τ, ρ)，以及全部类型训练的最终版本，写入 `FROZEN_PIPELINE.json` 并留 UTC 与 sha256 收据。然后为 24 个新评估 state 计算全部候选并按第零节各方法选择（每个 controller 用没见过其类型的留一类型折），全部选择在新 state 的第一个 rollout 提交前密封。

# 七、新 state 上的开发检验

**controller：** 与跨type4 B 部分的新 state 评估相同：环形交换场景流匹配策略 14 个、保守强化学习 6 个、5 种模型预测控制与优先级时空 A* 规划共 36 个、跨type3 的三个新类型；其余 8 个学习型类型不评估。

**动作：** 每 (controller, state, seed 0–1)：第零节表中本轮主方法与 5 个消融各自选中的动作、只加安全投影、人定双 η·第 500 步切换、人定双 η·按进度切换；相同物理动作只跑一次。

**开发目标（报告是否达到，不作确认性主张）：**

| 编号 | 内容 | 目标 |
|---|---|---|
| G1 不伤害 | 新 state 上只加安全投影 ≥ 98% 的 controller | 本轮主方法 − 只加安全投影 的点估计 ≥ −1pp；伤害数（低 ≥ 10pp）为 0；报告判为不修正的比例 |
| G2 不漏修 | 新 state 上只加安全投影 < 90% 的 controller | 本轮主方法 − 学习双 η·不判修不修·扩充提议 的 CI 下界 > −1pp；报告误判为不修正的比例 |
| G3 后期 η 更好 | 只加安全投影 < 90% 的 controller | 本轮主方法 − 学习双 η·critic 判修不修·只用冻结提议 的配对差与 CI；两个"不含"消融各自的贡献 |
| G4 相对人定时间表 | 全部评估类型，类型等权；另按类型列出，重点列 Transformer 行为克隆策略、环形交换场景流匹配策略、集中式模型预测路径积分控制 | 本轮主方法 − max(人定双 η·第 500 步切换, 人定双 η·按进度切换) 的配对差与 CI |
| G5 两种判修不修 | 同上 | 本轮主方法 − 学习双 η·探测规则判修不修·扩充提议 的配对差与 CI，分 G1、G2 两组 controller 报告 |
| G6 覆盖 | 覆盖子集（第 4.4 节） | 时间表生成器与切换时重查在同数量比较下是否优于冻结提议；与人定双 η·按进度切换的差是否缩小 |

**CI：** 按共同协议第四节，5000 次配对 bootstrap；类型等权时先类型、再 controller、再 state 成簇重抽（两个 seed 同簇）；"同数量样本内最佳"在每次重抽内重新计算。unknown 按下界计，另报上界。

# 九、执行顺序

1. 完整性审计（开始，含并行任务目录清单与 `squeue`）→ 复现与执行等价性测试（第一节）→ 开工记录与收据（探索与重查动作抽样、新 state 种子、判修不修的参数网格、规模上限）。
2. 训练 state 标签：探索动作、重查动作、只加安全投影补 seed 1。
3. 19 折：时间表生成器（嵌套选 checkpoint）→ critic（嵌套选 checkpoint 与权重）→ 两种判修不修的参数（嵌套）→ 留一类型检验。
4. 覆盖比较（第 4.4 节）。
5. 冻结 → 新 state 选择并密封 → 标签 → G1–G6。
6. 完整性审计（结束）→ 交付。

任何阶段被挡住时，把受影响的类型记为缺口并写明原因，继续其余部分。只有源码保护、DB 规则、复现门或执行等价性测试对全部类型都无法满足时才整体停下。

# 十、结论映射

| 观察结果 | 结论与下一步 |
|---|---|
| G1 与 G2 都达到 | 两步决定解决了"不会不修正"的问题：pipeline 学会了不卡就不修、卡了才修 |
| G1 达到、G2 不达到 | 判修不修偏保守，开始漏修；看误判 controller 的特征与 (k, δ) |
| 探测规则判修不修优于 critic 判修不修 | 修不修可以由简单的黑盒探测决定，不需要 critic；论文中把它作为 pipeline 的第一步 |
| G6 中时间表生成器或切换时重查优于冻结提议，且 G3 为正 | 后期 η 的提议是瓶颈，新来源补上了一部分；它成为 pipeline 的标准部件 |
| G6 有改善但 G3 不为正 | 提议变好了，但 critic 没能从中挑出来；下一步改 critic |
| G6 无改善 | 新来源也提不出好的后期 η；看 4.1 探索标签中成功的后期 η 分布，判断是否存在好的区域 |
| G4 的 CI 下界 > −1pp | 学出的两个 η 第一次在开发类型上追平人定时间表 |
