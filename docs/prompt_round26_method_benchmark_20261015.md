# 一、目的：在同一批测试集上，统一比较各类方法

我们的方法是“时间表动作菜单 + 无标签行为探测 R5 + 通用 critic A3”。到目前为止，各类方法分散在不同轮次、不同测试集上评估，彼此不可直接比较。论文需要一张统一的方法对比表：同一批测试 controller、同一套指标、同一种 CI。

每类方法在报告中都要标注它对应的文献范式：

| 代号 | 方法 | 对应的文献范式 |
|---|---|---|
| M0 | 部署默认：全选 F10 | 固定参数 |
| M1 | 源平均固定 η：在训练 controller 上平均成功率最高的固定臂 | robust 单策略 / 域随机化取平均 |
| M2 | 源平均完整菜单动作：通常为 S500 | 同上，但动作包含时间表；是增益调度（gain scheduling）的一种形式 |
| M3 | 静态描述条件 critic：controller 表示为 R3-PCA2，A3 同款架构 | 以任务描述为条件的价值函数 |
| M4 | 行为探测条件 critic：round16 冻结的 A3，表示为 R5-PCA2 | 从交互中推断上下文（类似 PEARL）/ 系统辨识式探测 |
| M5 | 规则 G_E：探测 → Ê → 规则 | 结构化的手工辨识 + 规则 |
| M6 | 逐实例少样本调参：在目标 controller 上用 k 条标签选臂，方法 E 与 Thompson | 上下文 bandit / 逐实例调参 |
| M7 | critic 先验 + 少样本修正：A3 的预测作为先验，用 k 条标签按 round8 方法 C 的方式修正 | 元学习先验 + 快速适应 |
| — | oracle（完整菜单）、oracle（固定菜单） | 参照 |

**M3、M4、M6、M7 都分别评估两种菜单：**
- 固定菜单：{F10, F13, F2}，以及该测试集里另有的固定臂；
- 完整菜单：加上时间表臂。

这样可以把“方法本身的作用”和“动作空间（时间表）的作用”分开。

# 三、设计（先写 PREREGISTRATION.md，附 UTC 时间与 sha256 收据）

**state 划分：** 每个测试 controller 按 state_uid 排序，前一半为校准池，后一半为评估集。
- 所有方法都在评估集上计算遗憾，保证可比；
- M6、M7 只能从校准池里抽标签；
- 零样本方法不使用校准池。

**少样本模拟：**
- k ∈ {1, 2, 4, 8, 16}（每臂的标签数），每个 k 重复 1000 次，随机种子写入预注册。
- 报告：总标签数，以及“达到 M4（零样本 A3）在同一测试集上的平均遗憾”所需的最小标签数。

**M3 的训练：** 架构、超参数与选 step 的方式，全部照 round16 中 A3 的设定，只把 controller 表示换成 R3-PCA2。fit seed 用 17、23、41。训练和冻结都必须在读取任何测试标签之前完成。

**指标：**
- 相对完整菜单 oracle 的平均遗憾与最大遗憾；
- 平均成功率；
- 灾难数（比 F10 低 ≥ 10pp 的 controller 数）；
- 使用的目标标签数。

CI 先在 controller 层重抽，再在 state 层成簇重抽，共 5000 次，使用配对比较。

**预注册判定：**

| 编号 | 检验内容 | 判定标准 |
|---|---|---|
| B1 | 零样本里 M4 是否最好 | M4（完整菜单）的平均遗憾低于 M0、M1、M2、M3（两种菜单）、M5。在 T1–T5 合并的结果上，每一对比较的配对 CI 上界 < 0 |
| B2 | 动作空间 vs 方法 | 对 M3、M4、M6 分别比较“完整菜单 − 固定菜单”的遗憾差，以及在固定菜单内“M4 − M1”的遗憾差。描述性报告二者的大小，并给出 CI |
| B3 | 样本效率 | M6、M7 达到 M4 零样本遗憾所需的标签数（若在 k = 16 以内都达不到，记为 > 16 × 臂数） |

# 四、结论映射

| 观察结果 | 结论 |
|---|---|
| B1 通过 | 在所有零样本方法中，“时间表 + 行为探测 critic”最好，可以作为论文的主方法对比 |
