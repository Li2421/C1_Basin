# 一、背景与问题

**论文定位：** 修正黑盒 controller 在安全层下产生的死锁。不同的黑盒 controller 需要不同的修法。

**round30h（`diagnostics/decentralized_fix_selection_v1/`，DEVELOPMENT）的结果：**
- 五个黑盒 controller 族、46 个实例、6 臂菜单：不修正、全程 η13、前 500 步 η13 之后 η10 的时间表、右手规则甲、乙、丙。
- 不看成败的诊断探测：只加安全层，300 步。
- 留一族的三分支规则选择器为 81.4%，比最好的单一固定修法（时间表，75.9%）高 5.57 个百分点，CI [0.37, 11.62]；critic 选择器未通过。
- 冻结比例完全区分了分布式模型预测控制与其余四族。
- 瓶颈：右手规则的参数在族间不迁移；"不修正"分支从未被选中。

这些标签此前都已打开过。**本轮做前瞻确认：** 冻结规则选择器，在五个族的新实例、全新 state 上检验。

# 二、冻结的规则选择器（在任何新探测与新标签之前写入预注册并留收据）

**主选择器：三分支规则。**
- 冻结比例高于阈值甲：选右手规则（组别见下）；
- 否则，若第 300 步的累计进展高于阈值乙：选"只加安全层、不修正"；
- 否则：选"前 500 步 η13、之后 η10 的时间表"。

阈值甲、阈值乙与右手规则的组别，用 round30h 的全部五族标签与诊断特征拟合：网格与目标函数与 round30h 相同，即各族等权的平均成功率最高；平局规则也与 round30h 相同。这一步只用已打开的旧数据，必须在任何新探测之前完成并冻结。

**次要选择器（探索性，不作主终点）：两级规则。**
- 与主选择器相同；但进入右手规则分支后，再按冻结比例是否高于阈值丙，在右手规则甲（强）与右手规则乙（弱）之间选择。
- 阈值丙同样用 round30h 的五族数据拟合并冻结。
- 它针对 round30h 中"右手规则参数不迁移"的瓶颈。

**对照：**
- 一律不修正、一律时间表、一律全程 η13、一律右手规则甲、乙、丙；
- 每族事后最优、每个 controller 事后最优；
- 冻结的通用 critic，只限它原来的菜单。

# 五、预注册的终点（CONFIRMATORY）

CI 先在 controller 层重抽，再在 state 层成簇重抽，共 5000 次，使用配对比较。每次重抽内重新确定"最好的单一固定臂"。unknown 按下界计，另报上界。合并时各 controller 等权，另报各族等权的结果。

| 终点 | 内容 | 判定标准 |
|---|---|---|
| 确认一（主） | 规则选择器是否优于任何单一固定修法 | 主选择器的平均成功率减去最好的单一固定臂，CI 下界 > 0 |
| 确认二 | 是否优于我们此前的默认做法 | 主选择器减去"一律用时间表"，CI 下界 > 0 |
| 确认三（描述性） | 每族是否选对 | 各族的修法类型准确率、各族成功率与该族最好固定臂之差、灾难数（比该族最好固定臂低 10 个百分点以上的 controller 数） |
| 次要（探索性） | 两级规则能否解决右手规则参数的问题 | 两级规则减主选择器；在分布式模型预测控制族上的差 |

| 观察结果 | 结论 |
