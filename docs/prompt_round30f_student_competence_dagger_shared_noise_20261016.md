# 一、背景与问题

**论文定位：** 修正黑盒 controller 在安全层下产生的死锁。分布式学生是其中一类黑盒学习型 controller。

**已有结果：** round30 至 round30d。14 个有效学生是从 14 个联合 MACFlow 教师蒸馏得到的分布式一步学生（MAC-Flow 第二阶段），坐标系一致，通过修正后的蒸馏门。

| 学生 | 只跑学生，不加安全层 | 只加安全层 | 前 500 步 η13、之后 η10 的时间表 |
|---|---|---|---|
| 10 个 global 学生 | 0%（碰撞 49%） | 0% | 94.5% |
| 4 个 local 学生 | 约 41% | 约 41% | 约 93% |

- 失败拆分：自身停滞 469 条（不加安全层也超时，且无碰撞），安全层导致的停滞 321 条（原本碰撞，加安全层后超时）。
- 只靠修正、不用学生时为 28.1%，说明学生与修正是协同的。

**问题：** 学生自己就不合格。要说明"修正修好了黑盒 controller 的死锁"，学生必须先是基本合格的策略：自己能完成大部分任务，只在交互时卡住。

**两个可能的原因：**
1. **离线蒸馏的误差累积：** 学生只在教师的数据分布上学习，闭环运行时偏离分布，进入没见过的状态。标准的对策是闭环重标注：让学生自己跑，在它到过的状态上请教师给出动作，再训练。
2. **各机器人的模式不一致：** 联合教师的一次采样同时决定 4 个机器人顺时针还是逆时针绕行；而每个学生只看到自己那一份噪声，各自抽到的模式可能相反，造成迎面冲突。

   不需要通信的对策是共享随机种子：事先约定一个种子，每个机器人在每一步都能算出同一份联合噪声，学生用它来协调绕行方向。这是"公共随机数"假设，不是通信。

**本轮问题：**
1. 闭环重标注与共享随机种子，能否让学生成为合格的分布式策略？
2. 学生合格之后，失败构成会不会从"自身停滞"转为"安全层导致的停滞"？
3. 修正与时间表的结论在合格学生上是否依然成立？

# 二、学生变体（对 14 个教师各训练两个新变体）

教师与 round30 至 round30c 相同：14 个冻结的联合 MACFlow，以 round30b 与 round30 的 TEACHERS.json 为准，先核对 hash。

| 全名 | 文件中的代号 | 内容 |
|---|---|---|
| 原学生（离线蒸馏、各自噪声） | V0 | round30（4 个 local）与 round30b 至 round30c（10 个 global）的有效学生。不重训，标签全部复用 |
| 闭环重标注学生（各自噪声） | V1 | 以 V0 为初始，做 3 轮闭环重标注 |
| 闭环重标注 + 共享随机种子学生 | V3 | 输入改为"自身观测 + 机器人编号 + 联合噪声"，先离线蒸馏，再做 3 轮闭环重标注 |

## 2.1 与 round30b 相同的部分

- **网络：** 官方 `actor_onestep_flow` 形式（宽度 512×4，学习率 3e-4），4 个机器人共享参数。
- **坐标系：** 目标动作与噪声都转换到机器人自己的径向/切向坐标系，按 round30b 的方式（`world_actions_to_local`、R_iᵀ）；部署时转回世界坐标并限速。local 教师保留原 local 定义。
- **教师动作与噪声：** 教师动作取 `native_fn(obs, k)` 的输出，噪声取 `trace_fn(obs, k)` 的第 0 步。数据集与闭环状态都不一定是 t0，直接构造 env 并 reset，不用 `make_env`。
- **蒸馏损失：** 学生输出与教师动作的均方误差。

## 2.2 共享随机种子（V3）的输入

- **联合噪声：** 4 个机器人的噪声分量 ξ_1…ξ_4，与教师采样所用的那一份完全相同。
- **转换：** 学生 i 把每个分量转换到自己的径向/切向坐标系中表示：
  - global 教师：R_iᵀ ξ_j；
  - local 教师：R_iᵀ R_j ξ_j。

  机器人 j 的径向方向，由学生 i 能观测到的量算出：自己的半径加上 j 的相对位置。
- **输入：** 机器人编号 one-hot、自身观测行、转换后的 8 维联合噪声。
- **部署：** 每个机器人用事先约定的键 `jax.random.fold_in(key_for(state, seed, step), 联合噪声标签)` 抽出同一份联合噪声（按教师坐标系的约定，各向同性高斯），再各自转换。联合噪声标签写入预注册。
- **单元测试：**
  - 把整个场景旋转任意角度，学生的全部输入不变；
  - 转换只用学生 i 能观测到的量；
  - 训练时的联合噪声，与教师采样所用的噪声逐位一致；
  - 改变其他机器人的目标，学生输出不变。

## 2.3 闭环重标注（V1 与 V3 都做 3 轮）

**每一轮：**
1. **采集：** 用当前学生 checkpoint，在 64 个训练 state 上各跑一局（seed 0）：一半只跑学生、不加安全层，一半只加安全层；都不加修正。
   - 训练 state 用 `ring_exchange` 的 `sample_initial_state(split = "train", seed)`，每轮用新的种子区间，事先算好写入预注册，并与 DB 中的评估、pilot、调参 state 去重。
   - 碰撞或到达终止时，该局停止采集。
2. **标注：** 在走过的状态中每 5 步取一个，在该状态的联合观测上请教师给出动作与噪声，按 2.1 的方式生成训练样本。
3. **训练：** 把新样本并入原数据与此前各轮的样本，从当前 checkpoint 继续训练 20,000 步。超参数与 round30 相同。

**冻结：** 3 轮之后的 checkpoint 就是该学生的最终版本，事先写死，不按闭环结果挑选。

**规模：** 28 个学生 × 3 轮 × 64 局 = 5,376 局采集，不入评估统计；训练用 GPU。

**V3 的离线初始训练：** 用原数据集，步数与 round30 相同，按 dev 蒸馏误差选 checkpoint，然后进入闭环重标注。

## 2.4 有效性门（在任何评估之前判定）

- **蒸馏门：** 沿用 round30c 修正后的门。三条全部满足才有效：
  - 选中的 checkpoint 不是 step 0；
  - 在教师动作 ≥ 0.10 m/s 的样本上，平均余弦 ≥ 0.90；
  - 误差 ≤ 0.05 m/s 的样本占比 ≥ 80%。

  检查样本为 round30b 的 2,048 个固定 state 与噪声键。V3 使用对应的联合噪声输入。

# 四、预注册的终点与判定

CI 先在 controller 层重抽，再在 state 层成簇重抽，共 5000 次，使用配对比较。V1 与 V0、V3 与 V1 都按同一个教师配对。unknown 按下界计，另报上界。

| 终点 | 检验内容 | 判定标准 |
|---|---|---|
| 能力一（主） | 闭环重标注能否让学生更合格 | 在"只跑学生"下，V1 − V0 的成功率 CI 下界 > 0。另报碰撞率之差 |
| 能力二（主） | 共享随机种子是否带来额外提升 | 在"只跑学生"下，V3 − V1 的成功率 CI 下界 > 0 |
| 死锁一 | 合格之后，安全层下是否仍会卡住，修正能否修好 | 对 V1、V3 分别检验："前 500 步 η13、之后 η10 的时间表"减去"只加安全层"，CI 下界 > 0 |
| 死锁二 | 是否优于公平调参的右手规则 | 对 V1、V3 分别检验：该时间表减去右手规则，CI 下界 > 0 |
| 时间表（描述性） | 时间表相对固定 η 的额外收益 | 最佳时间表减去最佳固定 η，按 round30 的定义 |
| critic（描述性） | 冻结 critic 能否选对 | 相对四个修正臂中事后最优者的平均遗憾；与一律用时间表的配对差 |
| 失败构成（描述性） | 能力提升后，失败来源如何变化 | 对 V0、V1、V3 分别报告：自身停滞与安全层导致的停滞的数量与比例，以及各臂救回的数量 |
| 与教师的差距（描述性） | 分散化的代价 | 每个变体与对应教师在同一分布式安全层下、同一臂上的成功率差 |

**证据等级：** V1、V3 的标签全新，以上终点为 CONFIRMATORY；V0 与教师的已有标签为 DEVELOPMENT 参照。

| 观察结果 | 结论 |
