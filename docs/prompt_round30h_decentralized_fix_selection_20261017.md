# 一、背景与问题

**论文定位：** 修正黑盒 controller 在安全层下产生的死锁。黑盒包括学习得到的模型、模型预测控制、A* 一类规划器。

**分布式安全层下，Ring 场景中各黑盒 controller 族的结果（round30 至 round30g、round30e）：**

| 黑盒 controller 族 | 只加安全层 | 前 500 步 η13、之后 η10 的时间表 | 公平调参的右手规则（各族分别调参） |
|---|---|---|---|
| 分布式学生（14 个） | 11.8% | 94.2% | 11.3% |
| 高斯行为克隆策略（6 个，共享观测） | 0% | 83.6% | 0% |
| 分布式模型预测控制（6 个） | 5.5% | 12.2% | 100% |
| A* 规划 controller（3 个合格实例） | 94.8% | 39.6% | 100% |

- **卡住的方式不同：**
  - 学习型策略是"在动但不前进"，很少完全停住；
  - 分布式模型预测控制在 83% 的超时局里出现完全停住，而且绕行方向混杂，是真正的多机器人僵持；
  - A* 规划 controller 本身基本合格，加修正反而变差。
- **冻结的通用 critic 对 18 个新实例全部选了时间表。** 它的菜单里没有"不修正"和右手规则。

**本轮问题：** 不同黑盒 controller 族需要不同的修法。能否先用一段不看成败的诊断探测，零样本地为每个 controller 选出合适的修法，包括"不修正"？这正是要学习的 controller 与 Q 的关系。

# 四、诊断探测（不看成败，在任何选择之前完成并冻结）

对每个 controller，在 16 个 probe state（与 R5 探测相同）上，用"只加安全层"跑 300 步，seed 0，关闭终止。记录下列特征，定义写入预注册：
- **冻结比例：** 未到达目标、且速度低于 0.01 m/s 的机器人·步所占的比例；
- **在动但不前进：** 速度不低于 0.01 m/s，但 2 秒内到目标的距离减少不足 0.05 m 的机器人·秒；
- **累计进展：** 第 100、200、300 步时，全队到目标总距离的累计减少；
- **安全层干预强度：** 安全动作与 nominal 动作之差的平均大小；
- **绕行方向混杂比例：** 沿用 round30g 的定义。

另外保留各 controller 已有的 R5 特征（缺的不补）。

这些探测不看任务成败，只用于选择。round30e 中右手规则的调参，用到了各族的调参 state 与结果，所以菜单中右手规则的参数本身带有族信息。报告中要如实说明这一点。

# 五、选择器与评估（留一族交叉验证）

**选择器：**
1. **规则选择器（预注册的三分支）：**
   - 冻结比例高于阈值甲：选右手规则；三组中选哪一组，由源族决定；
   - 否则，若第 300 步的累计进展高于阈值乙：选"不修正"；
   - 否则：选"前 500 步 η13、之后 η10 的时间表"。

   阈值甲、阈值乙与右手规则的组别，都只在源族上用网格搜索确定：取使源族平均成功率最高的组合。
2. **critic 选择器：** 结构与冻结的通用 critic 相同（MLP 64/64/16），输入为诊断特征加动作 one-hot。只用源族的标签训练，fit seed 17、23、41，选 step 的规则与 round16 相同。
3. **对照：**
   - 一律不修正、一律时间表、一律右手规则甲、一律右手规则乙、一律右手规则丙；
   - 冻结的通用 critic，菜单只限它原来能选的臂；
   - 每族事后最优：该族平均最好的一个臂；
   - 每个 controller 事后最优。

**评估：** 五折留一族。每一折：
- 只用其余四族的标签确定规则阈值、训练 critic；
- 在留出族的每个 controller 上做 controller 级选择；
- 记录成功率、相对"每个 controller 事后最优"的遗憾，以及灾难数。灾难：比该族最好的单一固定臂低 10 个百分点以上的 controller 数。

CI 先在 controller 层重抽，再在 state 层成簇重抽，共 5000 次，使用配对比较。unknown 按下界计，另报上界。
