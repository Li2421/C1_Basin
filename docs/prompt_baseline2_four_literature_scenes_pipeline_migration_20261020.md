- 成功判定：沿用现有流程的定义（全部到达，且无碰撞）；另外按论文的判据报告一份，作为参照。
- **state 集合：**
  - 窄通道场景与门口场景：论文的原始实例记为 state 0，单独报告；另在起点上加均匀扰动生成 63 个 state（窄通道场景扰动 ±0.05 m，门口场景 ±0.1 m；扰动后仍须满足间距要求），种子开工时写定；
  - 二维拥挤随机场景：每个 N 用 3.2 的采样器生成 100 个 state；
  - 圆形围场五机随机场景：用 3.3 的采样规则生成 100 个 state。
- **几何有效性：** 每个 state 都要检查单机器人有路（墙按半径膨胀后栅格搜索），以及容量是否足够。不满足的 state 剔除并列出，不得算作死锁。

**偏差声明：** 流程版改变了论文版的动力学（窄通道场景、二维拥挤随机场景与圆形围场五机随机场景原为二阶模型，门口场景原为独轮车），安全层也换成了我们的集中式投影。报告中每个结论都要写明来自哪个版本。

# 六、C 部分：流程版中的 controller

1. **名义朝目标控制器**（白盒，只作背景参照，不进入主结论）。
2. **8 个不需要训练的类型**（来自 `ZOO_MANIFEST.csv`）：交叉熵方法模型预测控制、分布式交叉熵方法模型预测控制、分布式模型预测控制、梯度下降模型预测控制、集中式模型预测路径积分控制、集中式随机采样模型预测控制、优先级时空 A* 规划、冲突搜索多机规划。每个类型的实例与参数照 `ZOO_MANIFEST.csv`。逐个检查实现是否写死了环形交换场景的几何或 4 台机器人：若是，就用子类改为从场景读取墙与机器人数，**不改算法与超参数**；改不了的类型记为缺口并写明原因。
3. **学习型试点**（第二优先级，第 1、2 项在全部场景完成后再做）：确定性行为克隆策略、混合密度行为克隆策略，各 2 个种子，训练代码与 config 照 `diagnostics/blackbox_families_v1/`。专家示范用冲突搜索多机规划在训练 state 上的成功轨迹。二维拥挤随机场景只在 N ∈ {8, 14} 上训练与评估。
   - **能力门槛（开工时写定）：** 在各 state 的单机器人版本上（只保留该机器人），只加安全投影时成功率 ≥ 95%，才算合格。不合格的实例照实报告，不进入第八节的主结论。

# 七、D 部分：只加安全投影的基线与失败拆分

每个 controller × 场景 × state × seed（0–1）跑"只加安全投影"。每台机器人每一局按以下互斥顺序分类：
1. **到达**；
2. **碰撞**；
3. **几何不可达**（第五节的检查）；
4. **静止未到达**（最后 W 步内位移小于半径，W 取 5 s 对应的步数）。再细分为：
   - 4a **滤波器平衡点死锁**：最后 W 步中至少 90% 的步上，投影改写了名义输入，名义输入非零，并且联合锥残差小于 τ = 0.05。联合锥残差的算法：取联合投影中起作用的约束行，其法向量记为 a_k，求 min over μ ≥ 0 of ‖u_nom + Σ μ_k a_k‖ / ‖u_nom‖（u_nom 为全体机器人的联合名义速度）；
   - 4b **被已到达者阻挡**；
   - 4c **名义输入为零**；
   - 4d **其他静止**；
5. **在动未到达**：再细分为振荡（路径长度大于位移的 5 倍）与缓慢前进。

敏感性：W ∈ {2.5 s, 5 s, 10 s}，τ ∈ {0.02, 0.05, 0.1}。

**判定场景是否可用于迁移：** 若某个场景中，所有合格的黑盒 controller 只加安全投影的成功率都 ≥ 98%，这个场景对迁移不提供信息，第八节只做 L1，并在报告中写明。

**描述性普查：** 对 4a 类事件记录起作用约束的组成、死锁簇大小、名义速度与约束法向量的夹角，以及让名义速度离开约束锥所需的最小修正的方向与大小（以平均约束法向量为第一轴的局部坐标），按 controller 类型比较分布。**只做描述，不下"共享"的结论。**

结果写入 `SAFETY_BASELINE.csv`、`FAILURE_DECOMPOSITION.md`、`GEOMETRY_CENSUS.md`。

# 八、E 部分：修正流程的迁移

三层，按顺序做：

**L1 固定修正（不重新训练）：** 全程 η10、全程 η13、人定双 η·按进度切换（先 η13，平均进度第一次 ≥ 0.968 或到时限的 6/7 时切到 η10）。η 的数值取自 `HISTORICAL_INVENTORY.json`，执行链照 round36。修正基与几何无关，所以这一层在四个场景上都适用。

**L2 冻结流程零样本：** 跨type6 的冻结流程（`FROZEN_PIPELINE.json`）中"学习双 η·进度阈值学出（不看 controller）"与"学习双 η·进度阈值学出·在线停滞触发"两种方法。先检查它们的输入（状态编码、机器人数）在新场景中是否有定义：
- 有定义的，原样加载冻结模型，零样本选动作，不重新训练；
- 没有定义的（例如状态编码写死了 4 台机器人或环形交换场景），记为"不适用"并写明原因，**不得为了能跑而改模型**。

**L3 场景内重新学习（尝试）：** 对每个通过第七节可用性判定的场景：
- 动作菜单：只加安全投影，加上从跨type6 冻结候选池中按开工时写定的种子抽出的 11 个 (前期 η, 后期 η, θ) 动作，共 12 个；θ ∈ {0.90, 0.93, 0.95, 0.968, 0.98}；
- 训练 state：每个场景 32 个（窄通道场景与门口场景取自扰动 state；二维拥挤随机场景取 N = 8 与 N = 14 各 16 个；圆形围场五机随机场景取 32 个）；
- 评估 state：每个场景另取 32 个，与训练 state 不重叠，seed 0–1；
- 标签：每个类型取 2 个实例 × 训练 state × 12 个动作 × seed 0；
- 模型：跨type6"不看 controller 的 critic"的结构与训练规则，状态输入换成按 `physical12` 定义为新场景写的 12 维特征；按 controller 类型做留一类型交叉验证，每个 controller 都用没见过其类型的那一折；
- 冻结后再在评估 state 上选动作并评估，选择在第一条评估 rollout 提交前密封。

**比较（每个场景单独报告，再报四个场景合并）：** L1、L2（若适用）、L3 各自相对只加安全投影的成功率差，以及 L3 − L1；按 controller 类型与类型等权合并报告。另报碰撞率、超时率、伤害数（只加安全投影成功而修正后失败的局数）。

# 十一、失败处理与无人值守

| 类别 | 包括 | 处理 |
|---|---|---|
| 整体停下 | 写入了只读位置；共享数据库规则被破坏；四个场景的论文版全部无法搭建 | 停下报告。只有这三种情况可以整体停下 |
| 主线 | 论文版复现、流程版场景、controller 移植、只加安全投影与失败拆分、L1–L3 | 作业失败先读日志。基础设施原因（节点故障、内存不足、Slurm 时限、被抢占）：未完成的部分按写定的案例与种子重新提交。实现错误：修正后只重跑受影响的部分，写进迭代日志。某个场景或类型确实做不了：记为缺口并写明原因，其余继续 |
| 非主线收尾 | 图、排版、第二优先级（交叉口、协作避碰调度与伪协作避碰策略） | 不得作为主线的前置条件。数值先写入 JSON/CSV 并封存，图最后单独生成。失败记入 `GAPS.md`，其余照常 |

- 协调器自己执行上表；运行期间至少每 30 分钟更新一次 `STATUS.md`（当前阶段、已完成量、阻塞原因、已采取的处理），并查看 `squeue`。只要还有不依赖受阻部分的工作，就继续做。
- 某个场景的论文版复现"不一致"，不阻止它的流程版继续，但该场景的所有结论都要标注"论文证据未复现"。
